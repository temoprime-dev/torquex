# База знаний MS4X для MS42 и сайт по ней

Инструмент: `MS42/tools/knowledge_base.py`. Данные: `MS42/knowledge/ms42_knowledge.json`.
Сайт (один автономный HTML-файл): `MS42/site/index.html`.

```bash
# проверка данных (каждый символ сверяется с XDF, каждый источник — с URL)
python3 MS42/tools/knowledge_base.py --check

# выборки
python3 MS42/tools/knowledge_base.py --stage 2 --verdict gated
python3 MS42/tools/knowledge_base.py --symbol ip_ti_tco_2_pl_ivvt_1__n__maf
python3 MS42/tools/knowledge_base.py --grep форсун --json

# сайт
python3 MS42/tools/knowledge_base.py --html MS42/site/index.html
```

## Зачем это нужно

Рецепты по MS42 живут в вики MS4X и на форумах, то есть в тексте, который
нельзя проверить. Здесь то, что мы реально используем, превращено в данные:

* у каждой записи есть **вердикт**, который говорит, что инструменты с ней
  делают: `implemented` (есть код), `gated` (пишется только по документу от
  клиента), `requires_data` (нужны логи/стенд), `research` (описано, но
  сознательно не предлагается), `refused` (не сделаем никогда);
* у каждой записи есть **источники** с URL и датой обращения, поэтому любую
  фразу можно проследить до первоисточника;
* каждый названный символ проверяется по определению MS42 — если символ
  исчезнет из XDF, тест упадёт.

Ничего из этого файла не является спецификацией оборудования: MS4X — это
сообщество, и его текст меняется. Поэтому статус «research» у доброй половины
записей: вики описывает способ, но у нас нет данных, чтобы утверждать результат.

## Что попало в базу (30 записей)

Ключевые для продукта:

| Запись | Вердикт | Смысл |
| --- | --- | --- |
| `checksums`, `memory-layout` | реализовано | раскладка 512 КиБ и три записи CRC16, доказанные на 16/16 образах |
| `vmax`, `rpm-limit`, `hardcut` | реализовано | ограничители, поддержанные ядром и генератором |
| `injector-scaling`, `injector-dead-time`, `fuel-consumption-gauge` | по документу | Stage 2: девять карт впрыска, кривая задержки, расходомер приборки |
| `maf-curve` | по документу | замена кривой только под документированный датчик |
| `exhaust-pops` | нужны данные | хлопки без подтверждённого отсутствия катализатора не пишутся |
| `ignition-ron`, `ignition-mbt`, `anti-jerk`, `catalyst-heating` | исследование | стенд и лог детонации, поэтому значений нет |
| `idle-speed`, `vanos-setpoints`, `camshaft-calibration`, `full-load`, `load-model-vo` | исследование | описано подробно, но без данных это догадка |
| `intake-disa` | исследование | MS4X прямо советует перенос карт M54 1:1 — у нас нет донорской прошивки MS43, значит переносить нечего |
| `dtc-suppression`, `checksum-disable` | отказано | подавление ошибок и отключение проверки целостности мы не продаём |

Полезные детали, зафиксированные по ходу разбора:

* MS42 сам интерполирует между картами RON91 и RON98 по выученному октановому
  фактору, поэтому «бины под RON 91/95/98» — это разные калибровки под
  измеренный запас по детонации, а не переключение карт;
* скважность форсунок: цель не выше ~90 %, потому что ЭБУ накладывает ещё
  холодное и полное обогащение, коррекции и переходные компенсации;
* расходомер приборки чинится делением `ip_fco_map_cor__pq_ main_col` на тот же
  множитель, которым масштабировались форсунки;
* у двух объектов XDF единицы подписаны неверно (`ip_iga_puc__n__tco` — «°C»
  вместо °CRK, `ip_t_puc_deacc__n__maf_mmv` — «mg/strk» вместо секунд), а у
  заголовка `ip_fco_map_cor__pq_ main_col` в середине лишний пробел;
* переключателя DMTL в определении 0110C6 нет, хотя вики его перечисляет.

## Сайт

`MS42/site/index.html` — один файл, без сети и внешних скриптов: поиск по
тексту, фильтр по вердиктам, раскрывающийся список источников. Сгенерирован из
того же JSON, поэтому сайт и данные не могут разойтись. Тест проверяет, что
страница автономна (нет `<script src>` и `<link rel="stylesheet">`) и содержит
все записи.

## Проверки

`MS42/tests/test_stages.py::KnowledgeBaseTests` проверяет: файл валиден; каждый
символ есть в XDF; каждая запись ссылается на известный источник; вердикты
Stage 2 — «по документу» (кроме тех, что требуют данных); реализованы именно те
записи, под которые есть код; выборки по стадии/вердикту/символу/тексту
работают; HTML автономен и содержит все записи; битый файл (неверная схема,
неизвестный источник, несуществующий символ) диагностируется, а не молча
принимается.
