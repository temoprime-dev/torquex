# Рабочий процесс MS42: от стока до файла для прошивки

Ниже — полный маршрут, который проходят инструменты репозитория. Прошивку делает
внешний флешер; репозиторий готовит **файл** и **документ**, но не пишет в ЭБУ.

## 0. Что где лежит

| Путь | Что это |
| --- | --- |
| `MS42/firmware/` | 16 стоковых образов 0110C6 (512 КиБ), 15 уникальных |
| `MS42/definitions/` | два XDF: 512K (проверяется на образах) и 32K (только для чтения калибровки) |
| `MS42/policies/stage_policy.json` | allowlist: что и в каких пределах разрешено менять |
| `MS42/tools/` | детектор, XDF-слой, раскладка таблиц, ядро патчинга, CRC, генератор, наряд |
| `MS42/tests/` | 133 теста, все прогоняются без машины |

## 1. Определить образ

```bash
python3 MS42/tools/analyze_firmware.py MS42/firmware/<файл>.bin
```

Инструмент определяет тип чтения (полный 512 КиБ, частичное 64 КиБ, калибровка
32 КиБ), находит `OSID` (`0110C6`) и идентификатор набора `91c6…`, проверяет все
присутствующие записи CRC. Для 64 КиБ и 32 КиБ присутствует только запись `cal`.

## 2. Проверить контрольные суммы

```bash
python3 MS42/tools/checksum.py MS42/firmware/<файл>.bin --report check.json
```

Код возврата 0 — всё сходится; 3 — есть расхождение (файл не сток или повреждён);
4 — отказ починки. Алгоритм и геометрия записей — в
[`CHECKSUM_RU.md`](CHECKSUM_RU.md). Если образ не сходится, работать с ним
нельзя: ядро патчинга всё равно откажет на `SOURCE_CRC_INVALID`.

## 3. Убедиться, что карта читается правильно

```bash
python3 MS42/tools/table_layout.py \
  --bin MS42/firmware/<файл>.bin --symbol ip_tib__n__maf
```

Инструмент доказывает раскладку: оси берутся из сопровождающих объектов XDF
(`ldp*`/`ldpm*`), проверяются точки, монотонность, диапазон оборотов и то, что
данные целиком лежат внутри защищённого блока `0x48000..0x4F843`. Ориентация
(порядок хранения) определяется по физической тенденции данных, а не на веру.
Полный обход — `--all`.

## 4. Превратить заявку в план

```bash
python3 MS42/tools/generate_patches.py \
  --bin MS42/firmware/<файл>.bin \
  --request MS42/examples/stage1_request.example.json \
  --out patches.json --report generation.json
```

Намерения и их параметры — в [`GENERATOR_RU.md`](GENERATOR_RU.md). Если в
заявке есть зажигание, топливо, popcorn, VANOS, кривая MAF или launch limiter,
они вернутся статусом `REQUIRES_DATA` с требованиями из
[`EVIDENCE_REQUIREMENTS_RU.md`](EVIDENCE_REQUIREMENTS_RU.md); файл патча при
этом не создаётся, а наряд явно перечисляет невыполненные пункты.

## 5. Собрать файл

```bash
python3 MS42/tools/calibration.py \
  --bin MS42/firmware/<файл>.bin \
  --patches patches.json \
  --out build/patched.bin --report patch.json
```

Ядро проверяет каждое изменение по политике (границы, квантование, монотонность
там, где она нужна, пересечения записей), пишет только разрешённые байты,
пересчитывает затронутые записи CRC и выполняет повторную проверку. Файл
появляется на диске только при статусе `WRITTEN` без отказов. Подробности —
в [`CALIBRATION_RU.md`](CALIBRATION_RU.md).

## 6. Проверить результат независимо

```bash
python3 MS42/tools/analyze_firmware.py build/patched.bin
python3 MS42/tools/checksum.py build/patched.bin
```

Ожидаемо: тип `full-flash-512K`, три записи CRC валидны, `OSID` и идентификатор
набора не изменились. Дополнительно полезно убедиться, что изменились только
запланированные адреса (`unplanned_byte_changes` в `patch.json` пуст).

## 7. Выпустить наряд клиенту

```bash
python3 MS42/tools/delivery_note.py \
  --generation generation.json --patch patch.json \
  --customer "<имя>" --out delivery_note.md
```

Наряд собирается только из отчётов: адреса и значения, источник каждого
значения, что запрошено и не выполнено, что проверять после прошивки, и статус
проверки «НЕ ВЫПОЛНЕНА». Пример — `MS42/examples/delivery_note.example.md`.

## 8. Что остаётся людям

* Прошивка внешним флешером (QuickFlash/MS4x Flasher и т. п.).
* Проверка на машине: логи, дорога, при необходимости стенд. До этой проверки
  файл — расчёт, а не подтверждённый результат.
* Решение о подъёме отсечки и снятии ограничителя принимает клиент; генератор
  требует явного `acknowledge_risk` и пишет это в наряд.

## 9. Ограничения, о которых нужно помнить

* Ограничитель скорости в MS42 активен постоянно; значение 255 км/ч — это
  фактически «порог недостижим». Модель «мягкая ступень `c_vs_max_1`, жёсткая
  ступень `c_vs_max_1 + c_vs_max_add` (отсечка бензонасоса)» взята из
  документации сообщества; она помечена как требующая дорожной проверки.
* Варианты 0110AD/0110CA в этом репозитории отсутствуют: подтверждён только
  0110C6, XDF обязан совпадать с прошивкой по идентификатору.
* 32K-XDF не проверен на локальном образе: 32 КиБ чтения в наборе нет, поэтому
  работа с ним — чтение/справка, а не пайплайн.
* Пара файлов в `firmware/` совпадает байт-в-байт (`M52TUB24 THAI RHD` и
  `M52TUB25 EU3 LHD`): это один и тот же образ под двумя именами, результат
  патчинга для них обязан совпадать.
