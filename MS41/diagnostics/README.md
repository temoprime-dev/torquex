# MS41 diagnostics bundle

Machine-readable description of every EDIABAS job, result and table that BMW's
own MS41 ECU description files (SGBD `*.prg`) expose over the diagnostic link.

## Provenance

BMW distributes these descriptions as encrypted BEST object files. The parseable
form used here is the *decoded* documentation published in
[`emdzej/ediabasx-docs-sgbd`](https://github.com/emdzej/ediabasx-docs-sgbd)
(`docs/sgbd/MS410DS0.md` … `MS411DS2.md`), which is generated by decoders such as
[`radelbro/BimmerDis`](https://github.com/radelbro/BimmerDis) and
[`emdzej/ediabasx`](https://github.com/emdzej/ediabasx).

- **No BMW binary is stored in this repository.** Raw `.prg`/`.grp` files are
  never committed; `fetch_ms41_sgbd.py` keeps decoded sources in the
  git-ignored `MS41/.cache/sgbd` directory.
- The data is BMW-derived and included here in decoded, restructured form for
  interoperability and right-to-repair, matching common practice in this
  ecosystem. It is reference material, not a certified BMW document, and is
  removed on request.
- Note that BMW has issued DMCA takedowns against repositories that host
  decompiled SGBD sources (for example `piersholt/ediabas-sgbd`, blocked since
  2022-11). Treat redistribution carefully and prefer pointing users at their
  own EDIABAS installation.

If you have your own EDIABAS / Tool32 / INPA install, regenerate everything
locally from your licensed files:

```bash
python3 MS41/tools/fetch_ms41_sgbd.py --from-org-dir "C:/EDIABAS/Ecu"
python3 MS41/tools/parse_sgbd.py MS41/.cache/sgbd/*.md --outdir MS41/diagnostics
```

`--from-org-dir` accepts already decoded `.md` sources or `.b1v` files produced
by BimmerDis (which still need decoding before they can be parsed).

## Contents

| File | Purpose |
| --- | --- |
| `ms41_sgbd_index.json` | per-variant ECU name, revision, job and table counts |
| `ms41_jobs.json` | every job with arguments and results |
| `ms41_channels.json` | canonical logging signal → job, result, and fast-RAM address, byte order, scale and offset |
| `ms41_logging_presets.json` | the four TorqueX logging profiles as concrete job/result lists with units |
| `ms41_aliases.json` | exact EDIABAS result and job names → canonical signal, consumed by `analyze_testo_log.py` |
| `ms41_faults.json` | `FORTTEXTE` fault location → German text (decoded DTC table) |

Covered variants: `MS410DS0`, `MS410DS1`, `MS410DS2`, `MS410DS3`, `MS411DS1`,
`MS411DS2`.

## Limits

- The decoded sources describe the ECU variant, not your specific software
  version. Verify a job against your own `.prg` before relying on it.
- `ms41_channels.json` marks each signal as available or listed under
  `unsupported_signals` per variant; missing signals are never silently assumed.
- RAW RAM address, scale and offset come from the `BETRIEBSWMATRIX` table and
  describe the fast serial polling path. They are not a substitute for the
  scaled `*_WERT` results returned by the EDIABAS jobs.
- Fault text is German, as published. Codes are the `ORT` values from
  `FORTTEXTE`; the `FUMWELTTEXTE` freeze-frame definition is parsed but not yet
  mapped into the fault report.
