# Ядро патчинга калибровок MS41

Файлы: `MS41/tools/xdf.py` (чтение/запись по XDF), `MS41/tools/calibration.py`
(планирование, применение, CRC, проверка), `MS41/policies/stage_policy.json`
(allowlist), `MS41/tools/table_layout.py` (доказательство раскладки таблиц),
`MS41/tools/log_evidence.py` (контракт логов), тесты — `MS41/tests/test_calibration.py`,
`MS41/tests/test_table_layout.py`, `MS41/tests/test_log_evidence.py`.

Статус: ядро работает и проверено сквозным прогоном на реальных fixture-ах.
Ни одна изменённая калибровка в машину не записывалась — единственный
пропатченный артефакт пока лежит вне репозитория.

## Что гарантируется

1. **Default deny.** Записать можно только символ, перечисленный в политике.
   Всё остальное — `SYMBOL_NOT_ALLOWED`, файл не пишется.
2. **Правка только калибровочной области.** План строится в координатах
   калибровки (0…0x6000), затем переносится на смещение образа (0 для
   partial-дампа, 0x14000 для полного 256K). Байты программы и хвост образа не
   меняются — это проверено и тестом, и `verify_application`.
3. **Сначала посчитать, потом записать.** `plan_patches` ничего не пишет и не
   создаёт выходной файл. `--out` записывается только при статусе `READY`.
4. **Пост-проверка обязательна.** После CRC-пересчёта набор изменённых байт
   сравнивается с планом плюс байты контрольных слов; любое лишнее изменение —
   `UNPLANNED_BYTE_CHANGES`, недописанный план — `PLANNED_BYTE_NOT_WRITTEN`.
5. **Вход доверяется только целому.** Исходный BIN обязан сам проходить свою
   CRC-цепочку (`SOURCE_CRC_INVALID` иначе), размер — 0x6000 или 0x40000.

## Конвейер

```
BIN ──► load_calibration ──► plan_patches ──► (READY) ──► apply_plan ──► verify_application ──► BIN
                              │                            │
                              └─ REJECTED: файл не пишется  └─ recompute_crc: 15 блоков
```

`verify_application` стоит последним намеренно: это мета-проверка, она ничего
не знает о плане, кроме его байтов, и ловит ошибку в самом применителе.

## Отказы планировщика

| Код | Когда |
| --- | --- |
| `SYMBOL_NOT_ALLOWED` | символа нет в политике (в т.ч. несуществующего) |
| `REQUEST_INVALID` | нет `symbol`, не число, индекс у константы |
| `INDEX_OUT_OF_RANGE` | индекс за пределами таблицы |
| `VALUE_NOT_REPRESENTABLE` | округлённое значение не влезает в разрядность |
| `QUANTIZATION_TOO_COARSE` | ошибка округления больше `max_quantization_error_percent` |
| `POLICY_MIN/MAX_VIOLATION` | значение вне абсолютных границ политики |
| `XDF_RANGE_VIOLATION` | значение вне `range_low/high` из XDF |
| `DELTA_TOO_LARGE` | относительное отклонение от стока больше `max_delta_percent` |
| `OVERLAPPING_WRITES` | два запроса пишут один и тот же байт |
| `MONOTONICITY_BROKEN` | правка таблицы ломает неубывание по оси значений |
| `TOO_MANY_CELLS` | ячеек в одном патче больше `max_cells_per_patch` |
| `SOURCE_CRC_INVALID` | исходный файл не проходит свою CRC-цепочку |
| `OUTSIDE_CRC_COVERAGE` | запись за пределами защищённой области (см. ниже) |

Предупреждения (не блокируют запись): `DELTA_FROM_ZERO` (сток равен нулю,
относительное правило не применяется) и `CRC_BYTES_REWRITTEN`
(информационные байты контрольных слов, ожидаемы).

Ошибка квантования считается относительно **запрошенного** значения, поэтому
у крупных величин она мала по определению: 6700 rpm при шаге 32 rpm
записываются как 6688 (−0.18 %), а 100 rpm при том же шаге — как 96 (−4 %) и
будут отвергнуты. В отчёте всегда рядом стоят `requested_engineering`,
`new_engineering` и `quantization_error_percent` — округление видно, а не
скрыто.

## CRC

Цепочка MS41: стартовое слово = big-endian 16 бит по адресу `0x000E`, ход с
`0x0000`, алгоритм CRC-16/ARC (отражённый полином `0xA001`), результат
хранится **little-endian** в конце блока, признак конца — указатель `0xFFFF`.
Partial-калибровка 0x6000 содержит 15 блоков и покрывает `0x0000…0x2D4C`;
последнее контрольное слово — `0x2D4A`. Все 13 fixture-ов проходят цепочку.

`crc_storage_offsets()` отдаёт абсолютные смещения всех контрольных слов,
`recompute_crc()` идемпотентен (повторный вызов не меняет байты).

**Граница покрытия.** Калибровочный блок длиной 0x6000 защищён не целиком:
цепочка кончается на 0x2D4A, дальше идут ~13 КБ, которые CRC не считает.
Во всех 13 фикстурах граница одна и та же (`crc_covered_end()`), и значение
попадает в отчёт как `crc_covered_end`. Запись за границу отвергается
(`OUTSIDE_CRC_COVERAGE`): такая правка прошла бы молча и без проверки.

**Смещение для полного дампа проверено.** Перебор всех чётных смещений
256K-образа по первому блоку цепочки даёт ровно одно совпадение — `0x14000`,
и на нём валидны все 15 блоков; по смещению 0 (код программы) цепочки нет.
Пара файлов с одинаковым variant `23414104` (full и partial) различается
36 байтами `0x5DFE…0x5E21` — это как раз область вне покрытия, `0xFF` в full
против данных в partial; обе цепочки при этом валидны. Это не порча файла, а
разное состояние незащищённого хвоста, и записывать в него нельзя.

## Что именно разрешено политикой

| Символ | Что это | Границы | Гейт поверх политики |
| --- | --- | --- | --- |
| `c_n_max` | ограничитель оборотов | 6200…6900 об/мин, ±6% | `acknowledge_risk` или лог |
| `c_n_max_hys*`, `c_n_max_max` | гистерезис отсечки | 0…512 / 0…7100 | интент `hardcut` |
| `c_n_hys_*_puc`, `c_n_min_lgrd_pu`, `c_tco_min_pu`, `c_pvs_grd_pu` | поведение на сбросе газа | узкие полосы | popcorn/overrun, отдельный лог |
| `id_maf_tab__v_maf_1__v_maf_2` (обе вьюхи) | кривая MAF | 0…1023 кг/ч, 256 ячеек | документированная кривая датчика (`maf_curve`) |
| `ip_tib__n__maf` | базовая таблица впрыска, 192 ячейки | 0…30 мс, ±50%, 256 ячеек | интент `injectors`: профиль с dead-time + лог с коррекциями, расхождение ≤ 10% |
| `c_var_vs_max_act` | штатный вариант «ограничение скорости активно» | 0 / 1 | `launch_limiter`: в стоке 0, без него `c_vs_max` не читается |
| `c_vs_max` | ограничитель скорости (VMAX) | 0…255 км/ч | `vmax` (дорожный лимит) или `launch_limiter` (< 100 км/ч — launch-режим) |
| `c_maf_max` | предел нагрузки по воздуху (LM_MAX) | 0…1389 мг/такт, ±30% | `maf_limits`: тот же коэффициент, что у кривой + лог насыщения датчика |
| `c_maf_max_diag` | порог диагностики ДМРВ (short to battery) | 0…1389 мг/такт, ±30% | то же; сдвиг обязателен, иначе диагностика срабатывает раньше |
| `ip_maf_min_ivvt__n__tco` | порог VANOS, механика (11×5) | 0…1301.85 мг/такт, 55 ячеек | `vanos_switch`: измеренное сравнение фаз, только «тёплые» столбцы |
| `ip_dri_maf_min_ivvt__n__tco` | порог VANOS, автомат (11×5) | 0…1301.85 мг/такт, 55 ячеек | то же; таблицы механики и автомата не взаимозаменяемы |

`max_delta_percent` — предохранитель от ошибки в направлении или опечатки, а не
физический предел: настоящий гейт там, где он указан в последнем столбце. У
таблиц VANOS процентного предела нет сознательно: смысл нового порога в том,
что часть строк уезжает далеко, и запрещать это процентом значило бы запрещать
саму работу. Гейт — измеренное сравнение, а не число в политике.
Число ячеек в патче ограничено так, чтобы полная таблица (192 или 256 ячеек)
проходила одним планом — иначе CRC-цепочка и пост-проверка теряли бы смысл при
ручном разбиении на куски.

## Проверка раскладки таблиц

Прежде чем писать в таблицу, нужно доказать, что она действительно та, за
кого себя выдаёт: что байты по адресу XDF читаются как значения нужной
размерности, что оси взяты из правильных `ld*`-спутников, а не «похожи на
первый попавшийся», и что ориентация (что по строкам, что по столбцам) не
перевёрнута. `table_layout.py` делает это без единого лога, по самому XDF и
бинарнику:

```bash
python3 MS41/tools/table_layout.py --bin stock.bin          # три ключевые карты
python3 MS41/tools/table_layout.py --bin stock.bin --all     # все карты со спутниками
python3 MS41/tools/table_layout.py --bin stock.bin --symbol ip_tib__n__maf --json
```

Что проверяется:

1. **Спутники осей.** У каждой карты ищутся кандидаты среди `ld*`-таблиц
   («List of data points for …»). Роль оси назначается по числу точек
   (совпало с числом столбцов/строк карты), при равенстве — по единицам:
   обороты на ось скорости, всё остальное — на ось нагрузки. Кандидат без
   совпадения по размеру не угадывается: карта получает проблему, а не ось.
2. **Декодирование.** Границы значений читаются через тот же `Scaler`, что и
   при записи: размерность, порядок байт, множитель и смещение попадают в отчёт.
3. **Ориентация.** У семейств, для которых направление известно и объявлено,
   сравниваются две раскладки (rpm по строкам против rpm по столбцам), и
   выбирается та, где нарушений ожидаемого тренда меньше. Ожидание — это
   *тенденция*, а не закон: у `ip_tib__n__maf` 68 из 180 шагов по оборотам
   растут, и ни один тренд не помечен как обязательный (`STRICT_TRENDS`
   пуст). Поэтому ненулевые нарушения не делают карту «сломанной»: они
   показываются числом, а вывод — `orientation: rpm_major` или
   `orientation: not checked` для семейств без объявленного тренда.

Результат на B28-фикстуре (16×12 @ `0x09F8`, оси `0x77C`/`0x796`,
12 значений нагрузки 50.01…700.17 мг/такт и 16 значений 640…6500 об/мин,
`rpm_major` при 68 нарушениях против 223 у транспонированной раскладки) —
это то, что позволяет MAF-кривой и топливным правкам опираться на адрес, а не
на догадку. `--all` честно перечисляет и неполные карты: у части таблиц
XDF не содержит спутника нужной длины, и это печатается как проблема XDF, а не
молча пропускается. Код возврата 1 — если в разобранном наборе есть проблемы.

## Логи как контракт

Часть решений (подъём отсечки, зажигание, топливо, потолок MAF) без логов
не принимается. Чтобы «логов нет» не превращалось в мёртвую ветку, введён
файл-контракт `MS41/examples/log_evidence.stub.json` и его валидатор
`MS41/tools/log_evidence.py`:

- `kind: "stub"` — заглушка, **все** значения обязаны быть `null`; заполненная
  заглушка отвергается (`STUB_WITH_DATA`), чтобы выдуманные числа не выглядели
  как измеренные;
- `kind: "real"` — обязан назвать `source`, перечислить `channels` и заполнить
  хотя бы одну секцию целиком;
- секция считается ответом только целиком: одинокий `max_safe_rpm` без флага
  `validated` — это не данные;
- генератор читает файл через `--evidence` и учитывает только то, что контракт
  реально подтверждает: `rpm_limit` с `validated: true` заменяет
  `acknowledge_risk`, а в патч-файл попадают `evidence: log_evidence:<файл>` и
  `found: max_safe_rpm=…`;
- всё неподтверждённое остаётся `REQUIRES_DATA` с указанием статуса секции.

## Использование

```bash
# 1. план без записи (по умолчанию: только отчёт в stdout)
python3 MS41/tools/calibration.py --bin ФАЙЛ.bin --patches MS41/examples/patches_hardcut.example.json

# 2. запись + машиночитаемый отчёт
python3 MS41/tools/calibration.py --bin stock.bin \
    --patches MS41/examples/patches_hardcut.example.json \
    --out patched.bin --report report.json

# 3. JSON в stdout (для автоматизации, --json)
python3 MS41/tools/calibration.py --bin stock.bin --json --patches ФАЙЛ.json
```

Выход: `0` — `WRITTEN`/`READY`, `1` — `REJECTED` или отказанная запись.
В отчёте разделены `value_bytes_changed` (значения, ровно по плану),
`crc_bytes_changed` (контрольные слова) и `total_bytes_changed`.

Формат запроса на патч:

```json
{"symbol": "c_n_max", "value": 6700, "note": "почему"}
```

Для таблиц добавляется `"index": 30`. Формат примера:
`MS41/examples/patches_hardcut.example.json`.

## Границы применимости

- Политика v1 трогает ограничители, две вьюхи MAF-кривой и базовую таблицу
  впрыска `ip_tib__n_maf` (только для интента `injectors`, у которого свой
  гейт: документированные форсунки + лог, подтверждающий коэффициент).
  Зажигание и фазы в неё не входят — их правка требует логирования и стенда,
  а не только корректного ядра.
- Запись идёт в копию файла на диске. Инструмент **не** прошивает ЭБУ; это
  отдельный шаг, и он требует аппаратной части (QuickFlash и совместимый
  интерфейс).
- Правило «MAF-кривая неубывающая» проверяется по всей таблице, но не
  проверяет физический смысл правки: можно построить формально корректную и
  при этом неверную кривую.
- MS41.0 и MS41.1 по калибровочному файлу не различаются — вариант ЭБУ
  остаётся входными данными.
- Единицы в XDF могут врать: у `ip_maf_min_ivvt__n__tco` поле `units` говорит
  `°C`, хотя описание — «switching threshold (air mass)», а квант равен
  нагрузочному (5.44706 мг/такт). Инструмент сообщает об этом
  (`XDF_UNITS_MISLABELLED`), а патч-файл указывает свои единицы; `calibration.py`
  использует их только для отображения, кодирование всегда идёт через объект XDF.
- Раскладка таблиц доказана только для семейств, у которых в XDF есть
  спутники осей. Карты без спутников (`id_add_knk__n` и другие) описываются
  как проблема, а не как «наверное, вот такая сетка».
- Все решения, зависящие от логов, упираются в контракт `log_evidence`:
  пока файл — заглушка, они остаются `REQUIRES_DATA`, и это ожидаемое
  состояние, а не незавершённая работа.
