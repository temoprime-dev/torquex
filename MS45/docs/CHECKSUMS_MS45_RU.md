# Контрольные суммы MS45: схема, доказательства, границы

Документ описывает **обе** контрольные суммы Siemens MS45.0 / MS45.1, которые
считаются по области калибровки, и то, что лежит за её пределами (там — ничего).
Схема не переносилась ни с MS42/MS43, ни с DAMOS/A2L: она **выведена по данным** и
проверена на всех доступных образах. Реализация — `MS45/tools/checksums.py`,
тесты — `MS45/tests/test_checksums.py`.

Дата: 2026-10-06.

## 1. Что проверено и на чём

| Что | Сколько | Результат |
| --- | --- | --- |
| Калибровки 116 КиБ (`MS45/firmware` + `MS45/firmware_spdaten/cal`) | 238 | CRC-32 — **238/238**, MO3 — **238/238** |
| Полное чтение внешней флеш 1 МиБ (`MS45/firmware_dumps/MS45.0_0044560BN_fullread_ORI.bin`) | 1 | CRC-32 **ok** (`90899C7E`), MO3 **ok** (`00630007 0CCD0A3D`) |
| Семейства прошивок | 10 | у каждого своё место пары MO3, см. §3 |
| Внутренняя флеш MPC 448 КиБ | 1 | **не поддерживается** (`MPC_IMAGE_UNSUPPORTED`) |

Тесты проверяют не только совпадение сумм, но и то, что пара MO3 лежит **ровно в одном
месте** каждого файла, а место совпадает с табличным для его семейства.

## 2. Сумма №1 — CRC-32/MPEG-2 (основная)

| Параметр | Значение |
| --- | --- |
| Алгоритм | CRC-32/MPEG-2 |
| Полином | `0x04C11DB7` |
| init | `0xFFFFFFFF` |
| отражение (refin/refout) | нет |
| xor-out | `0x00000000` |
| Область | калибровка `0x200..0x1D000` (в полном образе — `0x40200..0x5D000`) |
| Место хранения | калибровка `0x100`, **big-endian u32** (в полном образе — `0x40100`) |

Эталонный вектор: `crc32_mpeg2(b"123456789") == 0x0376E6E7` (тест
`TestCrc32Implementation::test_known_vector`); табличная реализация сверена с
побитовой на четырёх наборах данных.

Совпадение с описанием ms4x.net («Siemens MS45»): «The primary checksum you'll deal
with when editing values in the parameter space is found at 0x40100. The default
checked region is 0x40200-0x5CFFF. It is a 32-bit CRC, using polynomial 04C11DB7,
default initial value is 0xFFFFFFFF, no reflection, XOR out 00000000».

## 3. Сумма №2 — MO3 (дополнительная)

| Параметр | Значение |
| --- | --- |
| Вид | аддитивная сумма 32-битных **big-endian** слов |
| Начальное значение | `0x0123456789ABCDEF` |
| Область | калибровка `0x240..0x7C8` (354 слова) |
| Результат | 64 бита = `high`,`low`, каждая половина — BE u32 |
| Место хранения | **своё у каждого семейства**, см. таблицу ниже |
| Переключатель | `val_mo3_swi_cal_cks` (`0xA5` — сумма отключена) |

Диапазон задан парой указателей в **программной** области: в полном образе
`0x60620` / `0x60624` = `0xFFE40240` / `0xFFE407C8` (база `0xFFE00000`). Во всех
десяти программных образах SP-Daten (`*_mpc_448K.bin`, `*_ext_0x60000-0xFFFFF.bin`)
эти указатели **одинаковы**, то есть диапазон `0x240..0x7C8` инвариантен для MS45.0 и
MS45.1 всех уровней SW — поэтому в коде он константа с проверкой указателей при
наличии полного образа (при несовпадении — примечание в отчёте и отказ от пересчёта).

Место хранения определяется **по семейству** и подтверждается **поиском пары** в
файле: в каждом из 239 образов вычисленная пара встречается ровно один раз, и это
ровно табличное смещение.

| Семейство (SW) | Файлов | Смещение пары MO3 | Смещение `val_mo3_swi_cal_cks` | Переключатель в стоке |
| --- | --- | --- | --- | --- |
| `4560BL00S` | 7 | `0x587C` | `0x585F` | — (семейство не поддерживается ядром) |
| `4560BL30S` | 1 | `0x589C` | `0x587F` | — |
| `4560BM00S` | 32 | `0x5780` | `0x5763` | — |
| `4560BN00S` | 38 | `0x57AC` | `0x578F` | — (включая реальный дамп) |
| **`4560BO00S`** | **81** | **`0x5820`** | **`0x5803`** | `0x00` во всех 81 файлах |
| `4570LL00S` | 1 | `0x5A80` | `0x5A63` | — |
| `4570LL30S` | 6 | `0x5AA4` | `0x5A87` | — |
| `4570LM00S` | 7 | `0x5714` | `0x56F7` | — |
| `4570LN00S` | 8 | `0x5740` | `0x5723` | — |
| **`4570LO00S`** | **33** | **`0x57DC`** | **`0x57BF`** | `0x00` во всех 33 файлах |

RR-части (`MS45/firmware/MS45.1_457LO02S/*.part.bin`, 25 файлов) принадлежат
семейству `4570LO00S` и лежат по `0x57DC`; ещё одна часть (1 файл) — `4560BN00S`
(`0x57AC`). Совпадение с прежними наблюдениями (81 файл на `0x5820`, 58 на `0x57DC`)
объясняется просто: 58 = 33 файла `4570LO00S` + 25 RR-частей.

**Важно:** место пары у каждого семейства своё, перенос адресов между версиями
запрещён. В ядре это выражено таблицей `MO3_STORE_OFFSET` и отказом
`CAL_VERSION_UNSUPPORTED` для семейств, которых нет в таблице.

## 4. Структура заголовка калибровки (`0x000..0x240`)

Разбор подтверждён побайтово на всех семействах (пример — `4560BO00S`):

```
0x000..0x04F  ASCII-идентификатор: "BO00CO0R456O0B000044560BO00S0CO0..."  (в файле)
0x050..0x0FF  00 / FF, служебные поля
0x100..0x103  CRC-32 (сумма №1), BIG-ENDIAN                     <-- пересчитываем
0x104..0x10F  00 00 00 01 | FF E4 02 00 | FF E5 CF FF   -- дескриптор области CRC-32:
              count=1, область FFE40200..FFE5CFFF (= калибровка 0x200..0x1D000)
0x110..0x12F  FF ... (заполнитель)
0x130..0x147  00 00 00 02 | FF F4 00 00 | FF F4 01 6F | FF F4 02 00 | FF F5 CF FF
              -- дескриптор подписи: count=2, области FFF40000..FFF4016F и
                 FFF40200..FFF5CFFF
0x148..0x14F  00 00 01 70 (=0x170, смещение подписи) | 00 01 CE 00 (=0x1CE00, длина)
0x150..0x16F  FF ... (заполнитель)
0x170..0x173  00 00 00 10 -- счётчик: 16 слов
0x174..0x1B3  64 байта, разные в каждом файле (175 различных блобов)
              -- RSA-подпись; НЕ покрыта ни одной из сумм и НИКОГДА не изменяется
0x1B4..0x1FF  FF ... (заполнитель)
0x200..0x23F  служебное; 0x240 -- начало области MO3
```

Отсюда два практических следствия:

1. **Обе суммы лежат внутри области калибровки.** Ничего за пределами
   `0x40000..0x5CFFF` пересчитывать не нужно: ни в нижней области `0x00000..0x3FFFF`
   (там свой CRC-дескриптор на `0x1F800`, область `0x00000..0x1EFFF` — по данным
   проекта `dader34/BMWeb-Flasher`, и она не пересекается с калибровкой), ни в
   программной области, ни во внутренней флеш MPC.
2. **Подпись `0x174..0x1B3` неизменяема.** Любая правка калибровки делает её
   недействительной (подписанная область включает `0x40200..0x5CFFF`), а пересчитать
   её без приватного ключа BMW нельзя. Это не задача генератора, но это нужно явно
   писать в наряде: файл предназначен для путей прошивки, которые не проверяют
   подпись (см. `ANALYSIS_WEB_RU.md`, §3 и §5).

## 5. Порядок пересчёта (обязателен)

Область MO3 `0x240..0x7C8` **не пересекается** с местом хранения пары
(`0x57DC`/`0x5820`/…), поэтому пара считается независимо. А область CRC-32
`0x200..0x1D000` **включает** место хранения пары, поэтому:

1. считаем `high`,`low` по области `0x240..0x7C8`;
2. **записываем пару** по смещению семейства;
3. **заново** считаем CRC-32 по `0x200..0x1D000` (уже с новой парой);
4. записываем CRC-32 по `0x100`.

Ошибка «посчитать CRC до записи пары» ловится тестом
`test_patch_inside_mo3_changes_both` — он правит байт внутри области MO3 и требует,
чтобы после пересчёта файл проходил проверку.

## 6. Правила записи и защита от подмены

* Записываются **только** байты сумм: `0x100..0x103` и 8 байт пары MO3. Больше —
  ничего (`recompute` возвращает список изменённых абсолютных смещений).
* Путь ядра — `recompute_after_patch(source, patched)`:
  * исходный образ обязан пройти проверку **обеих** сумм, иначе `SOURCE_CRC_INVALID`;
  * место пары берётся из **проверенного исходника**, а не из правимого файла;
  * любое различие за пределами калибровки — жёсткий отказ `OUTSIDE_CAL_REGION`.
* Место пары проверяется поиском: если вычисленной пары нет в файле или она
  встречается больше одного раза — отказ `CHECKSUM_LAYOUT_UNKNOWN`.
* Образы MPC 448 КиБ и любые размеры, кроме 116 КиБ и 1 МиБ, отвергаются
  (`MPC_IMAGE_UNSUPPORTED`, `IMAGE_SIZE_UNSUPPORTED`).

## 7. Что НЕ является суммой (проверено и отброшено)

* Байты `0x174..0x1B3` — подпись, а не сумма (не покрыты ни одной суммой и меняются
  между сборками с одинаковой калибровкой).
* Третьей суммы по области калибровки нет: `_mon`-суммы MS43 сюда не переносятся, а
  аддитивные суммы по целому файлу не сходятся (проверялось).
* Указатели `0x60620/0x60624` лежат в программной области и являются **диапазоном**,
  а не суммой.

## 8. Команды

```bash
# проверка одного файла или каталога
python3 -m MS45.tools.checksums MS45/firmware/MS45.0_456BO00S_E83 --explain

# проверка всех калибровок и дампа
python3 -m MS45.tools.checksums MS45/firmware MS45/firmware_spdaten/cal MS45/firmware_dumps

# пересчёт (восстановление) в отдельный каталог
python3 -m MS45.tools.checksums MS45/firmware_spdaten/cal --repair /tmp/ms45_fixed

# тесты
python3 -m unittest MS45.tests.test_checksums
```
