# TorqueX — сайт генератора (`web/`)

Статический фронтенд к API `server/app.py`: главная сразу открывает мастер из
четырёх шагов; `app.html` оставлен как совместимый переход на `index.html`.
RU/EN, тёмная и светлая тема. Чистый HTML/CSS/JS без сборки, внешних CDN и
аналитики; все строки — в одном словаре `i18n.js`.

```
web/
├── index.html            мастер: шаг 1 (сток) → 2 (вариант) → 3 (опции) → 4 (результат)
├── app.html              совместимый переход на index.html (с query и hash)
├── versions.html         поддерживаемые версии (таблица из /versions) и ограничения
├── field-reports.html    журнал полевых проверок (реестр пока пуст)
├── help-read-write.html  как прочитать и записать ЭБУ
├── help-test0-log.html   как снять лог Test0
├── logs.html, logs.js    разбор лога + добровольная передача копии (docs/LOG_DONATION_RU.md)
├── privacy.html          что и как храним из переданных логов
├── style.css             тема (токены), компоненты, адаптив, a11y
├── config.js             настройки развёртывания (единственный файл, который правят)
├── i18n.js               словарь RU/EN (единственное место с текстами интерфейса)
├── ui.js                 шапка/подвал, тема, язык, безопасный Markdown, тосты
├── api.js                клиент /versions /detect /build и демо-заглушки
├── request.js            сборка заявки (одна на все ЭБУ; используется и в Node)
```

## Как открыть демо

Сайт работает **двойным кликом**: откройте `web/index.html` в браузере.

* По умолчанию живого API нет: если страница открыта с диска (`file://`),
  включается демо-режим автоматически.
* Тот же режим можно включить на сервере параметром `?demo=1` на любой
  странице, например `index.html?demo=1` или `versions.html?demo=1`.
* В демо-режиме ответы `/versions`, `/detect`, `/build` — **вымышленные
  заглушки** (`web/api.js`), файл никуда не отправляется, «скачивание»
  показывает текстовое пояснение. Страница версий показывает demo-заглушку,
  а не `VERSIONS_FAILED`.
* Свёрнутый блок сценариев доступен только на `index.html?demo=1`: успешная
  сборка, чужая версия ЭБУ, мусорный файл, отказ по гейтам (например, хлопки
  без подтверждений).

## Как подключить к API

1. Разверните сервер по `server/DEPLOY_RU.md` (uvicorn на `127.0.0.1:8081`).
2. Статику и прокси настройте по **`web/DEPLOY_RU.md`**: куда класть файлы,
   готовый `server {}` для поддомена или префикса `/torquex/`, заголовки
   безопасности и чеклист после развёртывания.
3. Префикс API задаётся в `web/config.js`:

```js
window.TORQUEX_CONFIG = {
  apiBase: "api",        // относительно текущей страницы: запрос → …/api/versions
  demoDonateUrl: "",     // заглушка доната для демо (реальный адрес отдаёт сервер)
};
```

* Сайт **всегда** ходит относительными путями; абсолютных адресов и внешних
  запросов в бандле нет. `apiBase` без ведущей косой черты — чтобы сайт
  работал и из подкаталога (`/torquex/`), а не только из корня домена.
* Живой адрес доната приходит с сервера полем `donate_url` (сейчас пусто —
  кнопка неактивна). Платёжных форм на сайте нет и не будет.

## Живой режим локально

```bash
# 1. окружение (venv держим вне дерева репозитория)
python3 -m venv ../.venv
../.venv/bin/pip install -r server/requirements.txt

# 2. бэкенд генератора
TORQUEX_IP_SALT=devsalt TORQUEX_GENERATOR_VERSION=dev-live \
  ../.venv/bin/uvicorn server.app:create_app --factory --host 127.0.0.1 --port 8081

# 3. в другом терминале — статика сайта + прокси /api/ на этот бэкенд
python3 web/tools/dev_server.py --host 127.0.0.1 --port 8123 --api http://127.0.0.1:8081
# сайт: http://127.0.0.1:8123/index.html
```

`web/tools/dev_server.py` — только стандартная библиотека: отдаёт файлы из
`web/` и проксирует `/api/…` на бэкенд без префикса. Если бэкенд недоступен,
страница получает JSON-502 и показывает человеческое «API недоступно», а не
трейсбек. На боевом домене статику отдаёт nginx (`web/DEPLOY_RU.md`).

### Что отвечает живой API

Прогон от 2026-10-08, `fastapi 0.142.4`, `uvicorn 0.54.0`, Python 3.11.2,
`TORQUEX_GENERATOR_VERSION=dev-live`. Стоки — из репозитория; клиентские файлы
в репозиторий не добавляются.

```bash
curl -s http://127.0.0.1:8081/health
# {"status":"ok","generator_version":"dev-live","max_upload_bytes":1048576}

curl -s http://127.0.0.1:8081/versions | head -c 200
# MS43 versions: [430069,430056,430037,430055,430066]
# MS45: 10 семейств, families_with_definitions: ["4560BN00S"], donate_url: ""
```

**Определение (`POST /detect`).**

```bash
curl -s -F "file=@MS45/firmware_spdaten/cal/MS45.0_0044560BL00S0IA3N_P7537853_cal_116K.bin" \
     -F "lang=ru" http://127.0.0.1:8081/detect
# 200 · platform MS45 · version 4560BL00S · image_type «калибровка 116 КиБ» · supported true
```

| Файл | Ответ |
|---|---|
| `MS45/.../cal_116K.bin` (116 КиБ) | 200, MS45 `4560BL00S` |
| `MS43/firmware_archive/E39_530__c6668528_Ca430066_Stok.bin` (512 КиБ) | 200, MS43 `430066` |
| `MS43/firmware_archive/*_Cal.bin` (64 КиБ) | `UNSUPPORTED_IMAGE`: «размер 65536 байт не похож ни на одно чтение MS41/42/43/45» |

**Сборка варианта 1 (`POST /build`).** Заявка — ровно та, которую собирает
`web/request.js` (её можно напечатать: `node -e 'console.log(JSON.stringify(require("./web/request.js").buildRequest({…}).request))'`).

MS43, полный заказ — обороты, скорость, RON98 с добавкой и хлопки с
подтверждениями:

```bash
curl -s -X POST http://127.0.0.1:8081/build \
  -F "file=@MS43/firmware_archive/E39_530__c6668528_Ca430066_Stok.bin" -F "lang=ru" \
  -F 'request={"stage":"stage1","variant":"v1","octane":"ron98","no_catalyst":true,
      "acknowledge_legality":true,"acknowledge_temperature":true,
      "intents":[{"id":"ign1","kind":"ignition","delta_deg":1.5},
                 {"id":"rpm1","kind":"rpm_limit","value":7000,"acknowledge_risk":true,"acknowledge_oil_pump":true},
                 {"id":"vmax1","kind":"vmax","value":250},
                 {"id":"pop1","kind":"popcorn","band":"light","no_catalyst":"катализатор удалён…",
                  "thermal_watch":true,"road_validation_plan":"проверка на закрытой площадке…"}]}'
# 200 BUILT · limits/popcorn/ignition → written · rollback и legal_notice на месте
```

MS45, та же заявка в форме этого ЭБУ (`rev_limit` со значением и коробкой,
`pops` с задержкой в секундах):

```bash
# 200 BUILT · job _RqYnK0nCUHcNn54 · image_size 118784 · ttl_seconds 900
#   limits → written  (id_n_max_mt 6520 → 6800 rpm; c_vs_max 250 км/ч)
#   pops   → written  (c_t_min_pu 0.24 → 0.5 с)
#   ignition → requires_data: «у семейства 4560BL00S адреса карт зажигания не доказаны»
#   manifest.result = {sha256, image_size, kind, changed_cells 22, changed_bytes 44, checksum_words}
```

**Скачивание (`GET /jobs/{id}/file`).**

```bash
curl -s -D- -o /tmp/out.bin http://127.0.0.1:8081/jobs/_RqYnK0nCUHcNn54/file
# 200 · content-type: application/octet-stream · content-length: 118784
# x-generator-version: dev-live
sha256sum /tmp/out.bin
# 1ef9dbba… — совпадает с manifest.result.sha256
```

**Отказы.** `GET /journal` без админ-токена → **403** (`REQUEST_INVALID …
[нужен админ-токен]`); сайт к журналу не обращается.
Сборка MS43 на стоках `E39_525__b137b5*_Ca430037_Stok.bin` → **422
`SOURCE_CRC_INVALID`**. Заявка с октаном и без намерений → **422**, причём
`rejections` приходит **пустым**, а причина (`[reject] NOTHING_REQUESTED: …`)
лежит только в тексте наряда — мастер её оттуда и достаёт (см. ниже
«Что нашёл живой прогон»).

**Квоты.** Сервер считает сборки на учётную запись: 10 в час и 20 в сутки
(`TORQUEX_LIMIT_ACCOUNT_PER_HOUR`, `TORQUEX_LIMIT_ACCOUNT_PER_DAY`,
`server/core.py`). При отладке это ловится быстро: 429 и `LIMIT_EXCEEDED`.
Счётчики держатся в памяти — перезапуск uvicorn их обнуляет.

### Что нашёл живой прогон

Ошибки сайта, исправленные в этом раунде (сервер не трогали):

1. `manifest.requires_data` приходит **объектами** `{id,title,code,why,needs[]}`,
   а мастер печатал их как `[object Object]`: в демо-данных там были строки.
2. Манифесты MS43 и MS45 устроены по-разному: у MS45 итог в `manifest.result`,
   у MS43 — в корне (`result_sha256`, `changed_cells`, `changed_bytes`).
   Строка «Изменено ячеек / байт» на MS43 показывала прочерки.
3. У отказов `REQUEST_*` список `rejections` пустой, и мастер показывал
   «Сервер недоступен» вместо настоящей причины.
4. У статуса пакета `requires_data` (строчными) не было CSS-правила — бейдж
   оставался серым.
5. **Подтверждение риска не спрашивалось.** Сайт отправлял
   `acknowledge_risk: false`, если галочка не стояла, а генератор сверяет
   запрошенное значение со стоком **из файла** и отказывает
   (`ACKNOWLEDGE_RISK_REQUIRED`). Живой прогон: MS43 `430066`, отсечка
   6500 об/мин — 422 уже после отправки. Сайт стокового значения не знает,
   поэтому теперь спрашивает подтверждение всегда, когда включён любой
   ограничитель, а сами галочки подняты из свёрнутого блока «Ещё опции» в
   видимый блок «Подтверждения».

Замечание к серверу (не исправляли, см. `MEMORY.md`): у отказов заявки причина
дублируется только в наряде; `rejections[]` и `manifest.findings` пустые.

## Как менять тексты

Все строки интерфейса лежат в `web/i18n.js` двумя словарями: `RU` и `EN`.
В разметке строк нет — только ключи `data-i18n="..."` (и `data-i18n-attr`,
`data-i18n-title` для атрибутов и заголовка вкладки).

1. Найдите ключ: например, `wizard.s3.pops_disabled` (тексты функций — по
   ключам `wizard.s3.*`, главная страница — `wizard.home_*`, `wizard.s1.*`).
2. Поменяйте значение **в обоих** словарях: наборы ключей RU и EN обязаны
   совпадать. Это проверяют и `tests/test_web_static.py` (чтением), и
   `web/tools/check_build_states.mjs` (исполнением файла).
3. Подстановки — фигурные скобки: `"home.support_ms45": "... {families} ..."`.
   Набор `{...}` в паре RU/EN тоже проверяется.

Важно: тексты **генератора** (наряд, манифест, сообщения отказов) приходят
с сервера и не переводятся интерфейсом — сайт показывает их как есть и честно
об этом пишет (`common.engine_language_note`).

## Как менять тему

Тёмная тема — по умолчанию, светлая включается переключателем в шапке или
системным `prefers-color-scheme` (выбор пользователя сохраняется в
`localStorage`, чтение — в `try/catch`).

Палитра — css-токены в начале `web/style.css`:

```css
:root            { --bg:#0f1216; --accent:#f2a63b; ... }   /* тёмная */
[data-theme="light"] { --bg:#f7f8fa; --accent:#9a5b06; ... } /* светлая */
```

Акцент — тёплый янтарь (приборная панель BMW, ≈605 нм). Меняя `--accent`,
проверьте контраст: `python3 -m unittest tests.test_web_static` считает
коэффициенты по токенам и падает, если пара «текст/фон» хуже WCAG AA (4.5:1)
или границы хуже 3:1. Красный фон не используйте — уровни предупреждений
(инфо/важно/стоп) различаются цветом и текстом одновременно.

## Проверки

```bash
# статика сайта: ссылки, ключи RU/EN, размер, доступность, запрет innerHTML
python3 -m unittest tests.test_web_static -v

# поведение: состояния кнопки «Собрать файл» + проход мастера в DOM
python3 -m unittest tests.test_web_behaviour -v

# то же напрямую, без unittest
node web/tools/check_build_states.mjs      # без внешних зависимостей
node web/tools/check_wizard.mjs            # нужен jsdom (см. ниже), иначе SKIP
node web/tools/check_logs.mjs              # нужен jsdom, иначе SKIP
node web/tools/check_live.mjs              # нужен поднятый API, иначе SKIP

# синтаксис всех скриптов сайта
for f in web/*.js; do node --check "$f" || echo "FAIL $f"; done

# заявки мастера прогоняются через настоящий генератор на реальных стоках
node web/tools/check_requests.mjs

# полный прогон проекта
python3 -m unittest discover

# в Windows — те же команды через python
python -m unittest tests.test_web_static -v
python -m unittest tests.test_web_behaviour -v
python -m unittest discover
```

`tests/test_web_static.py` считает видимые слова стартового мастера с учётом
RU/EN и динамических подписей, число видимых секций, меню и действий до
появления кнопки «Скачать». Тесты читают файлы как UTF-8, независимо от
системной кодовой страницы.

`check_requests.mjs` вызывает `tools/torquex.py build --dry-run` для MS41,
MS42, MS43 и MS45 и проверяет, что собранные мастером заявки принимаются, а
заявки без обязательных подтверждений (хлопки без правовой справки и
декларации) — отклоняются. Файлы при этом не пишутся.

### `check_build_states.mjs` — без зависимостей

Грузит `config.js`, `i18n.js` и `request.js` в `node:vm` и **исполняет** их.
Это прямой ответ на провал прошлого раунда: тогда сайт молча сломался от
синтаксической ошибки в словаре, а чтение файлов регулярками её не заметило.

Проверяет: файлы исполняются; наборы ключей и подстановок RU/EN совпадают;
умолчания октана (RON98 включает добавку +1.5°, RON95/RON91 снимают);
**20 состояний кнопки «Собрать файл»** — для каждого известно, активна ли
кнопка, какой текст стоит рядом и какое поле подсвечивается; у каждого
блокировщика есть `focus`, и это поле существует в `index.html`; текст
подсказки непустой и без неподставленных `{…}` на обоих языках;
`config.js` пригоден для раздачи с nginx (нет схемы и хоста, донат пустой).

### `check_wizard.mjs` — DOM, нужен jsdom

Грузит `index.html` в jsdom, исполняет скрипты в том же порядке, что браузер,
и проходит поток кликами: загрузка и определение; Stage 1 с 98-м бензином до
«Скачать»; «оставить как есть»; блокировщики; неподдерживаемая версия; сетевая
ошибка; отказ, причина которого есть только в наряде; VIN обязательный и
необязательный; демо-панель; переключение языка посреди потока.

### `check_live.mjs` — против живого API

То же, но без заглушек: страница грузится по HTTP с `dev_server`, скрипты
тянутся с него же, `/detect` и `/build` уходят в настоящий генератор на
реальном стоке из репозитория. Это и есть «живой прогон» — именно он вскрыл
все пять ошибок выше.

```bash
# два фоновых процесса из раздела «Живой режим локально», затем:
node web/tools/check_live.mjs
node web/tools/check_live.mjs --base http://127.0.0.1:8123 \
     --stock MS43/firmware_archive/E39_530__c6668528_Ca430066_Stok.bin \
     --reject-stock MS43/firmware_archive/E39_525__b137b57g_Ca430037_Stok.bin
```

Два сценария: успешная сборка (определение → RON98 → отсечка с
подтверждениями → «Собрать» → «Скачать», с проверкой, что «Изменено ячеек /
байт» заполнено и `[object Object]` нигде нет) и живой отказ генератора
(`SOURCE_CRC_INVALID` на стоке `430037`). В обязательный прогон этот скрипт не
входит: он требует поднятого сервера. Без jsdom, без сервера или без файлов
стоков печатает `SKIP` и выходит с нулём.

Результат прогона 2026-10-08:

```
API: {"status":"ok","generator_version":"dev-live","max_upload_bytes":1048576}

== живая сборка на реальном стоке
  /detect → ЭБУ MS43 · Версия 430066
  пустая заявка → «В заявке пока пусто. Включите хотя бы одно: топливо RON98 …»
  RON98 → зажигание включено, кнопка активна
  7000 об/мин → «Отсечку выше стоковой генератор не выпускает без подтверждения риска…»
  риск подтверждён → «Выше 6750 об/мин генератор требует отдельное подтверждение…»
  /build → Файл собран
  изменено ячеек/байт: 151 / 153
  адрес файла (относительный): api/jobs/job-id/file

== живой отказ генератора
  /build → Генератор отказал
  причина: Код отказа SOURCE_CRC_INVALID — исходный образ не проходит CRC

OK: сценариев 2, проверок 29
```

**jsdom в репозиторий не добавляется** — правило проекта: никаких зависимостей
npm в дереве проекта (это проверяет `tests/test_web_behaviour.py`). Ставьте его
рядом, вне репозитория:

```bash
cd ..                 # уровнем выше корня репозитория
npm install jsdom     # проверено на jsdom 30.1.2, Node 22
cd torquex_generator
node web/tools/check_wizard.mjs
```

Node ищет модули вверх по дереву каталогов, поэтому `node_modules` рядом с
репозиторием виден из `web/tools/*.mjs`, а в сам репозиторий ничего не
попадает. Если jsdom не найден, скрипт печатает `SKIP: …` и завершается кодом
0, а `tests/test_web_behaviour.py` помечает тест как пропущенный.

## Браузер и скриншоты

Проверки выше — Node и jsdom. Это **не** браузер: они не измеряют фактическую
высоту первого экрана, не ловят горизонтальную прокрутку и не показывают, как
реально выглядят цвета. В рабочей среде этого раунда браузера не было, и сайт
в браузере **не открывался** — утверждать обратное нельзя.

Порядок ручной съёмки:

1. Поднимите живой режим (раздел выше) или откройте `index.html?demo=1` —
   для скриншотов достаточно демо, файл никуда не уходит.
2. В DevTools включите device toolbar и снимите ширины **375**, **414**,
   **768** и **1440 px**.
3. Снимки: старт (шаг 1), определение (шаг 2), опции (шаг 3) в двух
   состояниях — кнопка серая с подсказкой «чего не хватает» и кнопка активная
   после выбора RON98, — результат (шаг 4) с блоками «что изменено» / «что не
   изменено» / «откат», правовой блок при включённых хлопках, пустое состояние
   страницы версий (остановите бэкенд) и журнала, светлая и тёмная темы.
4. Сохраните в `web/screenshots/` с именами вида `03-options-375.png`.
   Подробности и таблица экранов — `web/screenshots/README_RU.md`.

Каталог `web/screenshots/` исключён из проверки размера бандла.

## Безопасность и приватность

* Никакого `innerHTML` с данными сервера: только `textContent` и узлы DOM
  (проверяется тестом). Наряд рендерится маленьким безопасным Markdown-рендером
  на элементах, а не строкой HTML.
* Файл стока не сохраняется в `localStorage` и нигде на клиенте не остаётся:
  он уходит на сервер одним multipart-запросом и живёт в памяти сервера до
  15 минут (`server/DEPLOY_RU.md`).
* Размер файла проверяется до отправки (пусто/больше 1 МиБ — отказ на месте).
* VIN необязателен, не попадает в URL и не пишется в журнал открытым текстом.
* В репозиторий не добавляются стоки клиентов и файлы с VIN; демо использует
  только вымышленные данные.
* Заголовки безопасности ставит nginx, а не код сайта: примеры и чеклист —
  `web/DEPLOY_RU.md`.
