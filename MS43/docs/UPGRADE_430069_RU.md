# Обновление MS43 до MS430069 и запись файла в ЭБУ

Документ закрывает часть пункта 4 задания: веб-анализ «как обновляют софт до
430069 и куда файл можно залить». Все утверждения — со ссылками на источники;
там, где сообщество не согласно, стоит пометка «спорно».

## 1. Зачем 430069

* 430069 — **последняя заводская версия** для MS43 (2005 год). В MS4X Wiki
  калибровки E39 портированы с версии 430066 на код 430069; 430056 и более
  старые файлы оставлены «для истории» с рекомендацией переходить на 430069
  (<https://www.ms4x.net/index.php?title=Firmware_Files>).
* Практические причины: поддержка 6-ступенчатой коробки, круиз на 6-й передаче
  (на 430056 теряется), современная диагностика. Community patchlist
  (см. `PATCHLIST_RU.md`) официально нацелен на 430069 и полностью совместим
  только с ним.
* Файлы различаются по приводу (LHD/RHD — модель температуры выпуска/катализатора)
  и рынку (EU/US — диагностика и DMTL). Порядок выбора: модель/мотор → привод →
  рынок. У E39-калибровок в EU-варианте возможны коды по DMTL при установке на
  машину без него.

Вердикт: **подтверждено** — для наших фич (патчлист, LC/RAL, ignition cut,
M-cluster, DS2, MAF-FL) база должна быть 430069.

## 2. Нужен ли bootmode

Главный вопрос при обновлении. Ответ сообщества однозначен:

* **Обычное обновление 430056/430066 → 430069 bootmode НЕ требует**: это
  program-code, записывается «полным write» 512 КиБ в обычном режиме
  (`e46fanatics`, тема «MS43 flashing to MS430069»: «You do not need bootmode»;
  `m5board`, «Introduce and MS43 Software Upgrade from 430066 to 430069»: полное
  чтение 66 → **full write** 69 без правок → ключ off 10–15 с → запуск).
* **Bootmode нужен только** для виргинизации/перепривязки к другому EWS, для
  чтения уже «залоченного» ЭБУ и для восстановления после неудачной записи
  (заземление pin 104 на C167, 6–8 с, затем чтение/запись). Цитата из шапки темы
  патчлиста: «Bootmode flashing is only needed when you want to virginize the ECU
  and readapt it to another EWS module. Every other feature works without bootmode
  flashing!» (<https://www.e46fanatics.com/threads/ms4x-siemens-ms43-community-patchlist-for-tuner-pro.1255981/>).
* Почему это важно: файлы в MS4X Wiki **виргинизированные** (пустой VIN, пустой
  ISN). Если записать такой файл в bootmode, ЭБУ потеряет привязку к кузову. При
  обычной записи загрузчик/идентификация сохраняются, и после записи достаточно
  синхронизировать EWS через INPA.

Вердикт: **подтверждено**, «только полная запись без bootmode» — наш штатный путь.

## 3. Проверенный порядок обновления

Сводный рецепт (совпадает у m5board, MS4X Wiki и racehuggins):

1. Полное **чтение** текущего ЭБУ (512 КиБ) и сохранение бэкапа — обязательно
   (`racehuggins.com/documents/E46/Huggins%20Racing%20E46%20MS43.pdf`).
2. Корректный файл 430069 под модель/мотор/привод/рынок.
3. **Full write** 512 КиБ в обычном режиме (MS4X Dev Group Flasher, JMGarage,
   WinKFP, Chipster — см. §4). Время ≈120 с, питание стабильное.
4. Ключ off, 10–15 с (ЭБУ должен сохранить питание постоянной памяти).
5. Запуск. Если ЭБУ ранее был виргинизирован/перепривязан — **синхронизация EWS
   с DME через INPA** (в MS4X Flasher есть и штатная функция EWS3 sync), чистка
   ошибок, сброс адаптаций.

Особые случаи:

* **Пришли с 430056 EWS-delete**: рабочий рецепт сообщества — сначала записать
  430056 с EWS-delete в bootmode, затем 430069 обычной полной записью, затем
  синхронизировать EWS (INPA). Прямой EWS-delete на 430069 у части машин даёт
  ошибки 100/115/128 и «crank no start» — вердикт по этому пункту **спорно**:
  у части людей работает сразу, у части только через цепочку 56 → 69.
* **ЭБУ со свапа/с разборки** (не привязан к машине): bootmode + EWS-синхронизация;
  обычная полная запись secure-данные не перезаписывает
  (`e46fanatics`, «[MS4X] Dev Group Flasher For MS42 & MS43», p.6).
* **Незапуск после миграции с файла Daniel_F**: в патчлисте есть служебный
  `[PATCH] Daniel_F. 430056 Update Fix` (0x6361E) — применять только по факту
  незапуска.

## 4. Куда залить: инструменты

| Инструмент | Что умеет | Суммы | Примечания |
|---|---|---|---|
| **MS4X Dev Group Flasher** (ms4x.net, активация) | полное чтение/запись 512 КиБ (~120 с), EWS3 sync, сброс адаптаций, DS2 | пересчитывает «на лету» | рекомендованный сообществом; актуальная замена «Flashing tools»-страницы |
| **JMGarage Flasher** | bootmode и обычная запись | нет (нужен отдельный корректор) | первый инструмент в старых инструкциях; в MS4X-темах заменяется дев-флешером |
| **WinKFP** | заводская запись/обновление | заводские суммы | подтверждено в теме MS43 tuning («I updated to v69 using WinKFP») |
| **Chipster MSS5X Flasher** | быстрый/медленный режим | **баг с порчей сумм** | из-за него исторически советовали Checksum Bypass; мы этим инструментом не рекомендуем писать |
| **Корректоры сумм** (Ultimo / MS43 checksum) | правка CRC в файле | — | нам не нужны: суммы считает наше ядро |

Ограничение из шапки патчлиста: правки возможны **только с полным 512K-файлом**,
универсальные флешеры (KESS и подобные) для MS43 не годятся.

## 5. Грабли, зафиксированные сообществом

* Запись в bootmode виргинизированного файла **без VIN/ISN** → машина не
  заводится; лечится записью VIN/ISN и синхронизацией EWS.
* «Помощь» в виде `[PATCH] Checksum Bypass` даёт ошибку **115 TPS-Adaption** на
  430069 (проверено на трёх прошивках, ошибка уходит после снятия патча) — мы
  этот патч не предлагаем, суммы считаем сами.
* Провал записи «кирпичит» ЭБУ до перезаписи через bootmode; INPA в этом
  состоянии может не видеть блок. Всегда нужен бэкап и умение войти в bootmode.
* Через несколько дней после первого запуска полезно перечитать блок, очистить
  ошибки и адаптации (рецепт из темы «MS4X Flasher update from MS430066 to 0069
  failed… SOLVED»).

## 6. Правила нашего проекта

* Генератор выдаёт **только полный образ 512 КиБ** для MS430069; частичная
  запись калибровки в нашем продукте не используется, потому что все фичи
  (патчи) правят и program-область.
* Суммы всегда пересчитываем своим ядром (`MS43/tools/checksum.py`), поэтому
  «Checksum Bypass» в наш пресет не входит никогда.
* В наряд печатаем: исходную версию софта, целевую (430069), список патчей и
  калибровок, требование полного бэкапа, необходимость синхронизации EWS, если
  ЭБУ был виргинизирован, и предупреждение про bootmode-восстановление.
* Иммобилайзер/виргинизация — только с подтверждениями `immo_change` /
  `immo_virginize` (см. `PATCHLIST_RU.md` §5): это операции уровня «машина
  теряет штатную защиту».
