# Генератор MS43: Stage 1 и Stage 2 (`MS43/tools/stages.py`)

Пункт 4 задания: «генератор → Stage 1/2 → хлопки/лимитер/launch → наряд → тесты
→ русские документы». Файл собирается как **набор пакетов**: пакет либо пишет
значения через ядро (`calibration.py`), либо честно отвечает `REQUIRES_DATA` со
списком нужных замеров. Догадок в файле не бывает.

```bash
# Stage 1 на стоковом железе: ограничители + launch control из заявки
python3 MS43/tools/stages.py --stage stage1 \
  --bin MS43/firmware/Siemens_MS43_MS430069_E46_M54B30_EU4_LHD.bin \
  --request MS43/examples/stage1_request.example.json \
  --out build/stage1.bin --report build/stage1.manifest.json --note build/stage1.md

# Stage 1 с хлопками: профиль либо прямо в намерении заявки (пример так и
# собран), либо отдельным файлом клиента через --popcorn
python3 MS43/tools/stages.py --stage stage1 \
  --bin <сток>.bin --request MS43/examples/stage1_request_popcorn.example.json \
  --out build/stage1_popcorn.bin
python3 MS43/tools/stages.py --stage stage1 \
  --bin <сток>.bin --request заявка_с_хлопками.json \
  --popcorn MS43/examples/popcorn.example.json --out build/stage1_popcorn.bin

# Варианты 2/3 с логами: доказательства выданы анализатором
# (см. docs/PACKS_LOG_REQUIREMENTS_RU.md §7.1) и лежат рядом в examples/logs —
# запускать из каталога примеров, чтобы относительные пути сошлись
cd MS43/examples && python3 ../tools/stages.py --stage stage1 \
  --bin ../../firmware/Siemens_MS43_MS430069_E46_M54B30_EU4_LHD.bin \
  --request stage1_variant_v3.example.json --out ../../build/stage1_v3.bin

# Stage 2: без блока hardware заявка отклоняется целиком
python3 MS43/tools/stages.py --stage stage2 --bin <сток>.bin \
  --request MS43/examples/stage2_request_intake.example.json --out build/stage2.bin
```

## 1. Пакеты

| Пакет | Статус | Что это |
|---|---|---|
| `limits` | **пишется на всех покрытых версиях** | ограничитель скорости (`c_vs_max_mt_1`/`_at_1` + `c_vs_max_add`) и обороты по передачам (`id_n_max_*__gear` мягкий, `id_n_max_max_*__gear` жёсткий) |
| `features` | **пишется только на 430069** | фичи патчлиста по запросу: launch control + RAL, отсечка зажиганием, MIL-детонация, кластер M3, DS2-логирование, VSS-fix. На 430037/430055/430056/430066 — отказ `PATCHLIST_FEATURE_UNSUPPORTED` для **любого** фичевого намерения (basedata патчлиста снята с 430069, маски на других версиях не доказаны); на 430069 фичи, которых в генераторе нет, отклоняются `PATCHLIST_FEATURE_NOT_IMPLEMENTED` |
| `popcorn` | **пишется на всех покрытых версиях** | хлопки: полосы `light`/`medium`, подтверждение «катализатора нет», план проверки, задержка; пишется только калибровкой (карты ПХХ + A/C-пара + задержка) — отдельного патча хлопков в патчлисте нет, поэтому пакет работает и на 430037/430055/430056/430066 |
| `full_load` | ждёт данных | пороги полной нагрузки (`id_pvs_fl__n`, `id_pvs_fl_ivvt__n`, `id_pvs_fl_vim__n_vim`) |
| `vanos` | ждёт данных | задания валов на полной нагрузке (лог фаз + стенд) |
| `ignition` | ждёт данных | RON91/RON98 (`ip_iga_ron_91/98_pl_ivvt__n__maf`) — детонация + топливо |
| `fuel` | ждёт данных | обогащение на full load (`ip_ti_fl__n`) — широкая лямбда |
| `maf` | ждёт данных | кривая ДМРВ (256 точек с даташитом/стендом) и пороги диагностики |
| `intake`, `injectors`, `exhaust` | ждёт данных | описание железа и паспорта/логи |
| `torque` | ждёт данных | модель момента и лимитеры (см. `TORQUE_RU.md`) |
| `disa_off`, `isa_off`, `idle`, `fan_thermostat` | ждёт данных | опции варианта 1 (`docs/TASK_VARIANT1_RU.md` §1): DISA off, ISA off, холостой ход, вентилятор/термостат. Запрос не отказ заявке: в наряде — причина и список того, что нужно от клиента (механика, логи, подтверждения), см. `tools/variant1.py` |

`REQUIRES_DATA` — не «ошибка»: файл при этом собирается из тех пакетов, которые
готовы, а наряд печатает список замеров, без которых соответствующий пункт не
делается.

Политика выбирается по версии из образа: 430069, 430056, 430037, 430055, 430066 —
каждая со своими адресами (из определения этой версии) и границами (из её
стоков). Версии нет в реестре (например, 430064 — нет полного стока) → отказ
`CAL_VERSION_UNSUPPORTED`; 64 КиБ чтение → `IMAGE_SIZE`. Что именно пишется на
какой версии — таблица в `VERSION_COVERAGE_RU.md` §3.

## 2. Ворота (реализованы в коде, проверяются тестами)

| Ворота | Правило |
|---|---|
| `ACKNOWLEDGE_RISK_REQUIRED` | значение выше стока (отсечка/ограничитель скорости) — без `acknowledge_risk: true` заявка отклоняется |
| `ACKNOWLEDGE_OIL_PUMP_REQUIRED` | отсечка выше `oil_pump_ack_rpm` (6750) — нужно отдельное `acknowledge_oil_pump: true` |
| `HARD_BELOW_SOFT` | жёсткая отсечка ниже мягкой — отказ |
| `NLS_NOT_IMPLEMENTED` | NLS в патчлисте не реализован — отказ (обещать нельзя) |
| `POPCORN_AGGRESSIVE_REFUSED` | полосы `aggressive`/`extreme`/`flames`/`gunshots`/`bang`/`hard` отклоняются по имени |
| `POPCORN_NO_CATALYST_REQUIRED` | письменное подтверждение «катализатора нет» (≥10 символов) |
| `POPCORN_THERMAL_WATCH_REQUIRED` | согласие следить за температурой выпуска и ОЖ |
| `POPCORN_ROAD_PLAN_REQUIRED` | план первых заездов и отката на бэкап |
| `POPCORN_BAND_VIOLATION` | значения вне полосы (об/мин, угол, задержка хлопка: `light` ≤1.0 с, `medium` ≤2.5 с) |
| `PATCHLIST_FEATURE_UNSUPPORTED` | любое «фичевое» намерение патчлиста на версии, кроме 430069: `launch_control`, `ral`, `ignition_cut`, `mil_knock`, `m_cluster`, `ds2_logging`, `vss_fix`, `maf_hack`, `maf_full_load`, `map_reduction`, `alpha_n`, `fuel_cut_cruise`, `boost`, `immo_bypass`, `immo_virginize` |
| `PATCHLIST_FEATURE_NOT_IMPLEMENTED` | фича есть в патчлисте, но генератор её не собирает (`maf_hack`, `maf_full_load`, `map_reduction`, `alpha_n`, `fuel_cut_cruise`, `boost`, `immo_bypass`, `immo_virginize`) — отказ и на 430069, чтобы файл не выглядел полным |
| `HARDWARE_REQUIRED` | Stage 2 без блока `hardware` — отказ целиком |
| `OCTANE_PROFILE_UNKNOWN` / `OCTANE_PROFILE_CONFLICT` | профиль топлива не распознан или задан противоречиво (поле заявки `octane` и намерение `kind: octane`) |
| `OCTANE_PROFILE_NO_ADDITION` | профиль RON95/RON91: добавка зажигания не пишется (карты стоковые, карта RON91 остаётся полом) |
| `ACKNOWLEDGE_LEGALITY_REQUIRED` | хлопки (`popcorn`) и слой диагностики (`dtc`) без `acknowledge_legality: true` — отказ до расчёта пакетов |

Плюс `REQUIRES_DATA` для пакетов без данных и обычные проверки ядра (границы,
квантование, CRC, пост-проверка).

Отдельно и **раньше всех** работает защита по версии калибровки
(`REVIEW_CLAUDE_RU.md`, задание 1): генератор читает код версии из образа
(`0x70008` в 512 КиБ, `0x8` в 64 КиБ чтении) и берёт политику этой версии из
реестра `VERSION_POLICY_FILES`; если версии в реестре нет — отказ
`CAL_VERSION_UNSUPPORTED`, 64 КиБ чтение — `IMAGE_SIZE` с указанием прочитанной
версии. Поддерживаются **430069** (калибровка + патчлист), **430037**,
**430055**, **430056**, **430066** (только калибровка: адреса — из определения
версии, границы — из её стоков). На 430069 фичи патчлиста работают, на остальных
версиях запрос фичи патчлиста отклоняется кодом
`PATCHLIST_FEATURE_UNSUPPORTED`. Почему нельзя переносить адреса между
версиями — таблица в `CALIBRATION_RU.md` §5a, полное доказательство по каждой
версии — `VERSION_COVERAGE_RU.md` §2. Версия и список поддерживаемых видны в
манифесте (`cal_version`, `supported_software`) и в наряде.

## 3. Launch control и RAL

Это фича патчлиста, поэтому **только 430069** (на других версиях — отказ
`PATCHLIST_FEATURE_UNSUPPORTED`; сам патч снят с 430069, маски на версиях
430037/430055/430056/430066 не доказаны).

`{"kind": "launch_control", "mode": 1, "rpm": 4000, "vmax_kmh": 30}` →
патч `[PATCH] Launch Control & Rolling Anti Lag` + `c_conf_lc` (1 — по
сцеплению, 2 — по сцеплению и круизу), `c_n_max_lc`, `c_vs_max_lc`.
`{"kind": "ral", "pvs_min": 60}` → `c_conf_ral = 1` и порог педали
`c_pvs_min_ral`. Дефолты `[DATA] LC & RAL Default Values` применяются патчем, а
затем перекрываются значениями из заявки — порядок «патчи → калибровка»
проверен тестом.

## 4. Хлопки (профиль клиента)

| Полоса | Добавка к гистерезису ПХХ | Угол зажигания при ПХХ | Задержка хлопка |
|---|---|---|---|
| `light` | 0..600 об/мин | −6..0° | 0..1.0 с |
| `medium` | 0..2000 об/мин | −12..0° | 0..2.5 с |

Профиль: `rpm_add`, `angle`, `no_catalyst` (строка-подтверждение),
`thermal_watch: true`, `road_validation_plan`, опционально
`minimum_rpm_guard.requested` (6 значений минимальных оборотов ПХХ) и
`delay_seconds`.

Задержка пишется на всех покрытых версиях: `c_t_puc_deacc_vs` (на месте) и
`ip_t_puc_deacc_1..5__n__maf_mmv` (по передачам, 6×4). Источник — MS4X wiki
«Siemens_MS43» → «Exhaust Pop Modifications» (timered pops), стоки сняты со всех
образов: 0..0.325 с на месте, 0.13..2.45 с по передачам. В XDF у этих таблиц
единицы подписаны `mg/stk` — это единицы осей, а значения дают секунды по шкале
`0.00017066667*X` (см. `VERSION_COVERAGE_RU.md` §4). Вместе с основными картами
пишется пара «A/C on» (`ip_iga_accin_puc__n__tco`, `ip_n_min_accin_puc__n__tco`),
иначе поведение менялось бы при включённом кондиционере. Хлопки «на месте»
(таблицы `id_n_hys_min_puc_*`) остаются `REQUIRES_DATA`: нужны логи EGT/лямбды.

## 5. Вариант 1 («Stage 1 базовый»)

Состав (задание `docs/TASK_VARIANT1_RU.md` §1): базовые зажигание/топливо плюс
одобренные владельцем функции — каждая **отдельным намерением** заявки. Ворота
самих функций не ослаблены: хлопки и диагностика по-прежнему требуют
«катализатора нет», фичи патчлиста — версии 430069, добавка по логам —
доказательства.

| Намерение | Что делает |
|---|---|
| `octane` (`fuel`: `ron98`/`ron95`/`ron91`) или поле заявки `octane` | профиль топлива; добавку зажигания получает только RON98 (≤ +1.5° без лога, ≤ +3° с логом детонации). RON95/RON91 — стоковые карты зажигания; карта `ip_iga_ron_91_pl_ivvt__n__maf` не изменяется никогда |
| `popcorn`, `dtc` | хлопки и слой диагностики «без катализатора»: нужны `no_catalyst: true` **и** `acknowledge_legality: true` |
| `rpm_limit`, `vmax` | ограничители оборотов/скорости по существующим воротам (`acknowledge_risk`, выше 6750 — `acknowledge_oil_pump`) |
| `launch_control`, `ral`, `ignition_cut`, `mil_knock`, `m_cluster`, `ds2_logging`, `vss_fix` | патчи 430069 (на других версиях — отказ `PATCHLIST_FEATURE_UNSUPPORTED`) |
| `disa_off`, `isa_off`, `idle`, `fan_thermostat` | ждут данных клиента (см. `REQUIRES_DATA`-блок в наряде) |

**Правовая справка.** Хлопки, удаление катализатора и диагностический слой
получают в наряд и манифест блок со ссылками (Регламент (ЕС) 715/2007 ст. 3
п. 10 и ст. 5 п. 2, Правила ЕЭК ООН № 83, Clean Air Act § 203(a)(3),
40 CFR § 1068.101(b)) — русский и английский текст, дата проверки. Это справка,
а не юридическая консультация; генератор требует подтверждения клиента.

**Откат на сток.** В манифест и наряд идёт поле `rollback`: sha256 стока
(исходного образа), порядок возврата и напоминание сверить хэш. Для MS43
проверка выпущенного файла — по sha256 из манифеста (режим `--verify-manifest`
реализован в генераторе MS45; перенос в MS43 — отдельная задача).

## 6. Наряд

`--note` пишет русский Markdown-наряд: клиент, стадия, **профиль топлива**,
исходный и итоговый sha256, применённые патчи с подтверждениями, таблица правок «было → стало» с
ошибкой квантования и источником, изменённые CRC, список невыполненных пакетов
с конкретными замерами, замечания ворот и инструкция по заливке (полный образ
512 КиБ, bootmode не нужен, бэкап, синхронизация EWS при необходимости,
температурный контроль, и отдельная строка: **прирост в л.с. без стенда не
обещается**). Если в заявке есть хлопки/диагностика — перед «Как заливать»
печатается раздел «Правовая справка» (RU + EN), а перед ним — «Откат на сток»
(sha256 стока и порядок возврата).

Манифест (`--report`) — машиночитаемый JSON того же содержания (для архива и
для `superpowers`-цепочек вида MS42/M сгенерированных отчётов).

## 9. Сетка значений

У части объектов крупный шаг (0.375 °CRK у зажигания, 32 об/мин у отсечек,
0.46875° у педали), поэтому «сырое» число из заявки почти никогда не ложится
точно. Генератор сам прижимает запрошенные значения к сетке объекта
(`_snap`), поэтому в наряде стоит достижимое число, а не ошибка квантования.
Для будущих пакетов, которые будут строиться по логам (зажигание, топливо), это
значит: либо значения тоже прижимаются к сетке в генераторе, либо объекту нужен
свой допуск квантования в политике — иначе ядро (порог 1 %) отклонит таблицу с
мелким шагом и большими по модулю значениями.
