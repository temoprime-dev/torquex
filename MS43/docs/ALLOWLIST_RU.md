# Allowlist MS43 (`MS43/policies/stage_policy.json`)

Пункт 3 задания: собрать allowlist со **своими** именами MS43 (имена MS42 не
искать), адресами и границами — из определения XDF и стоковых образов.
Сделано: **97 символов** — 63 калибровочных MS43 (включая группу `puc` и
справочные символы модели момента, [`TORQUE_RU.md`](TORQUE_RU.md)) + 34 символа
фич из community patchlist ([`PATCHLIST_RU.md`](PATCHLIST_RU.md)); у каждого есть
источник и заметка, 23 объекта помечены «только чтение». Это политика **430069**;
на 430037/430055/430056/430066 собираются свои политики из 62..63 калибровочных
символов ([`VERSION_COVERAGE_RU.md`](VERSION_COVERAGE_RU.md) §3).

* Каталог символов: `MS43/tools/policy.py` (`CATALOG`).
* Готовая политика: `MS43/policies/stage_policy.json` (генерируется).
* Тесты: `MS43/tests/test_policy.py` (в том числе тест «файл политики совпадает
  с каталогом» — политика не может разойтись с кодом).
* Пересобрать и посмотреть таблицу:

```bash
python3 MS43/tools/policy.py --build --report        # 430069: JSON + таблица
python3 MS43/tools/policy.py --build-all             # все политики версий
python3 -m unittest discover -s MS43/tests -t .
```

## 1. Как получены значения (и почему им можно верить)

| поле | откуда берётся |
| --- | --- |
| адрес, `size_bits`, форма (`rows x cols`), единицы, уравнение | определение MS4X XDF **этой версии** (512K) и community patchlist; **в политике адрес — абсолютное смещение в образе 512 КиБ** (в XDF он относительный, `BASEOFFSET 0x70000` прибавляется при сборке) |
| `min` / `max` | объявленный диапазон XDF (`rangelow/rangehigh`), а где его нет — весь диапазон сырого значения через масштаб объекта (например 8 бит × 32 об/мин → 0..8160) |
| `stock` (min/max, варианты, «одинаково во всех») | измерено по стокам **этой версии** прямо при сборке политики: для 430069 — 18 полных образов `MS43/firmware/*.bin`, для 430037/430055/430056/430066 — их образы из `MS43/firmware_archive` (полные 512 КиБ и чтения 64 КиБ, 3..11 файлов на версию) |
| `source`, `note` | веб-анализ (`MS43/docs/STAGE1_WEB_ANALYSIS_RU.md`) и MS4X wiki; без источника символ в каталог не попадает |

Проверки, без которых политика не выпускается (`validate_policy`):

1. каждый символ существует в определении XDF;
2. **любое** стоковое значение лежит внутри `min..max` — политика не имеет
   права резать сток;
3. границы представимы сырым значением при масштабе объекта (8 бит × 32 об/мин
   не может дать 9000);
4. у имени, которое в XDF объявлено дважды, обязан быть указан `xdf_index`
   (иначе непонятно, какие байты писать). В определении MS43 такое имя есть —
   тест находит его автоматически и требует индекс;
5. таблица с `require_monotonic` проверяется на монотонность стока (для ДМРВ).

## 2. Что в политике

Политика собирается **на версию**: поле `software` — это версия, на которой
политика проверена целиком, а не «известные версии MS43». Ядро читает код
версии из образа, берёт политику этой версии из реестра (`VERSION_POLICY_FILES`
в `policy.py`) и отказывает всем остальным (`CALIBRATION_RU.md` §5a). Сейчас
политики есть для 430069 (калибровка + патчлист), 430056, 430037, 430055 и
430066 (только калибровка); у 430064 полного стока нет — отказ. Разбор,
источники и доказательства по каждой версии — `VERSION_COVERAGE_RU.md`.

## 3. Ворота (продуктовые, реализуются генератором)

Политика — это пределы **данных**. Продуктовые правила живут в генераторе и
сравнивают запрос с `stock` из этой политики:

* **выше стока** (отсечка, пороги) → `acknowledge_risk`;
* **выше 6750 об/мин** → отдельное `acknowledge_oil_pump` (порог записан в
  политике как `oil_pump_ack_rpm`; таблицы представимы до 8160, но штатный
  масляный насос — известное слабое место, измерений у нас нет);
* **хлопки** — только при подтверждённом отсутствии катализатора; `c_conf_cat`
  в политике помечен «только чтение» именно потому, что это признак для ворот,
  а не ручка настройки;
* **Stage 2** привязан к комбинации железа, а не к названию;
* **community-порты** (E39, Z3, M52TUB28): VIN не проверяется, совместимость
  проверяется перед записью; файл `…E39_M54B25_EU4_LHD.bin` вообще исключён из
  эталонов — у него не сходится cal-сумма (см. `CHECKSUM_RU.md` §5).

## 4. Чего в политике нет — и почему

* **Символы фич без патча** — LC/RAL, MAF-FL, map reduction, MIL-индикатор,
  кластер M3, DS2, CAN-индикатор: в политике 430069 ячейки есть, но генератор
  пишет их **только вместе с соответствующим патчем** (поле `requires_patch`),
  иначе калибровка бесполезна или вредна. Сами патчи — `MS43/tools/patches.py`
  ([`PATCHLIST_RU.md`](PATCHLIST_RU.md)). В политиках 430037/430055/430056/430066
  символов фич патчлиста нет вовсе: его basedata снята с 430069, а байтовые
  маски на других версиях не доказаны.
* **NLS (no-lift shift)** — в патчлисте не реализован (категория «Not Implemented
  Yet»), поэтому символов NLS в политике нет и клиенту он не обещается.
* **Checksum bypass** — не пишем: суммы считаем сами
  (`MS43/tools/checksum.py`); внешне подтверждённый вред — ошибка 115
  TPS-Adaption на 430069.
* **Иммобилайзер** — в политике только чтение/учёт: `[PATCH] Immobilizer Bypass`
  и `[PATCH] Clear Immobilizer Data` требуют подтверждений `immo_change` /
  `immo_virginize` и записи в bootmode (см. `PATCHLIST_RU.md` §5).
* **Хлопки «агрессивным пресетом»** — публичного пресета нет; полосы
  `light`/`medium` собираются из `puc`-группы под конкретную машину. Сама
  `puc`-группа — 14 символов: карты ПХХ, пара «A/C on», задержка хлопка
  (`c_t_puc_deacc_vs` + `ip_t_puc_deacc_1..5__n__maf_mmv`); хлопки «на месте»
  (`id_n_hys_min_puc_*`) в политику не входят — нужны логи EGT/лямбды.
* **VANOS, зажигание, топливо сверх логов** — символы в политике есть, но
  изменение без логов/стенда не генерируется: генератор вернёт `REQUIRES_DATA`
  со списком замеров (детонация, широкополосная лямбда, целевые фазы).
* **Донорская линия MS42←MS43** — не тронута: `MS42/donor` использует своё
  определение MS43 и свои тесты (243 OK).

## 6. Дальше

Ядро читает политику так же, как MS42 читает свою: символ → `PolicyEntryData` →
квантование сырого значения → запись только внутри границ → `requires_patch`
(при необходимости — патч через `MS43/tools/patches.py`) → пересчёт CRC
(`MS43/tools/checksum.py`) → пост-проверка. Сделано к 2026-10-06: лимитер,
хлопки без катализатора (полоса + задержка), сборка политик на пять версий
(`--build-all`). Ждут данных: зажигание, топливо, VANOS, ДМРВ, форсунки, впуск,
выпуск, момент — списки замеров в `VERSION_COVERAGE_RU.md` §6.
