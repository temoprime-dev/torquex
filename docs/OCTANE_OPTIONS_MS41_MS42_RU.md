# Октан-профиль и опции варианта 1 на MS41/MS42 (шаг 1.4 задания)

Дата: 2026-10-07. Задание: `docs/TASK_FINISH_RU.md` шаг 1.4. Источник вердиктов —
веб-анализ `docs/VARIANT1_WEB_ANALYSIS_RU.md` (§5 DISA, §6 ISA, §7 октан,
§8 вентилятор/термостат/launch), проверка объектов — по определениям и стокам
репозитория.

## 1. Что решено и почему

| Функция | MS42 | MS41 |
| --- | --- | --- |
| Октан-профиль RON91/95/98 | **выбор клиента**: RON98 — добавка только через `ignition` и по логу детонации; RON95/RON91 — карты стоковые | **`REQUIRES_DATA`**: пары карт RON91/RON98 нет, семантика `ip_iga_tra_fac__tia__ron_fac` на стоке не доказана |
| `disa_off` | **`REQUIRES_DATA`** с конкретными нуждами (код положения, механика, лог до/после) | **неприменимо**: функции DISA у MS41 нет (нет объектов и job-ов) |
| `isa_off` | **`REQUIRES_DATA`** (лог ХХ, заглушка канала, решение по коду) | **`REQUIRES_DATA`** (те же требования; объекты ISA у MS41 есть) |
| `idle` | **`REQUIRES_DATA`** (лог установившегося ХХ) | **`REQUIRES_DATA`** (лог ХХ; уставка поднимается вместе со скважностью) |
| `fan_thermostat` | **`REQUIRES_DATA`** (объекты ECF/ECT есть, нужен трек-клиент и границы по температуре) | **недоступно**: объектов ECF/ECT в определении MS41 нет |
| `launch` | **отказ** (`INTENT_UNAVAILABLE`): патча для MS42 нет; лимиттер по передачам — `launch_limiter` и по логу | **отказ**: патча нет; лимит по скорости на старте — `launch_limiter` |
| `dtc`/`cat_delete`/`sap_delete` | **отказ**: проект подавление кодов и удаление систем контроля выбросов не выпускает | то же |

Ключевое правило: где нет доказательства — `REQUIRES_DATA` с перечнем «что дать
клиенту»; где объект физически отсутствует — отказ с причиной, а не «ждём
данных» и не молчаливое игнорирование.

## 2. Октан: почему именно так

У MS42 (как у MS43/MS45) база зажигания считается по двум картам,
`ip_iga_ron_91_pl_ivvt__n__maf` и `ip_iga_ron_98_pl_ivvt__n__maf`, с
интерполяцией по выученному октановому фактору; отдельные карты сдвига при
детонации — `ip_iga_aj_ron91__n__maf` / `ip_iga_aj_ron98__n__maf`
(веб-анализ §7). Отсюда:

* RON98: правится RON98-карта, добавка — только через `ignition` (ворота лога
  детонации из `docs/pack_log_requirements.json`); карта RON91 остаётся
  защитным полом;
* RON95: карты стоковые, ЭБУ сам интерполирует между 91 и 98;
* RON91: то же плюс консервативный режим (работает штатная защита).

Запрошенная добавка угла на RON95/RON91 — отказ до планирования
(`OCTANE_PROFILE_NO_ADDITION`), файл не выпускается. Неизвестное топливо —
`OCTANE_PROFILE_UNKNOWN`; расхождение поля заявки и намерения —
`OCTANE_PROFILE_CONFLICT`.

**MS41**: пары RON91/RON98 нет вовсе; есть базовая карта и температурно-октановый
фактор `ip_iga_tra_fac__tia__ron_fac`. Семантику фактора на стоке мы не
доказывали (ни по DAMOS, ни по стокам), поэтому полноценные профили не
выпускаются: намерение `{"kind": "octane", "fuel": "ron98"}` возвращает
`REQUIRES_DATA` с таблицами (и их адресами), нужными логами и воротами (штатные
knock- и термозащиты не ослабляются).

## 3. Что появилось в коде

**MS42**
* `MS42/tools/stages.py`: пакеты `octane` (kind `octane`) и `disa_off` /
  `isa_off` / `fan_thermostat` (kind `option`); `_octane_package` (выбор клиента,
  ворота добавки, отчёт в манифест и наряд), `_option_package` (причина + нужды
  из `tools/variant1.py`); `UNAVAILABLE_INTENTS` с отказами (`launch`,
  `dtc`, `cat_delete`, `sap_delete`); профиль топлива виден в CLI и в payload
  (`octane`).
* `MS42/tests/test_stages.py`: класс `Variant1Tests` (11 тестов) — профиль и его
  отчёт, запрет добавки на RON95/RON91, отказ при неизвестном/противоречивом
  профиле, ожидание `REQUIRES_DATA` для опций, наличие всех символов пакетов в
  определении, отказ `launch`, разбор примера заявки.
* `MS42/examples/stage1_request_variant1.example.json` — пример заявки варианта 1.
* `MS42/docs/STAGES_RU.md`: таблица Stage 1 и раздел «Октан-профиль и опции
  варианта 1».

**MS41**
* `MS41/tools/generate_patches.py`: evidence-записи `octane`, `isa_off`, `idle`
  (таблицы, логи, стенд, ворота) и `UNAVAILABLE_INTENTS` с отказами для
  `disa_off`, `fan_thermostat`, `launch`, `dtc`, `cat_delete`, `sap_delete`.
* `MS41/tests/test_generate_patches.py`: класс `Variant1Tests` (4 теста) — план по
  октану, ворота на файле `ip_iga_tra_fac__tia__ron_fac`, отказ неприменимых
  опций, ожидание лога ХХ для `isa_off`/`idle`.
* `MS41/docs/EVIDENCE_REQUIREMENTS_RU.md`: §5 с вердиктами по октану, ISA off,
  холостому ходу и таблицей «чего на MS41 нет вовсе» (разделы 6–8
  перенумерованы).
