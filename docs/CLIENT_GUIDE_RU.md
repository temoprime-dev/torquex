# TorqueX: гайд клиента (RU) — прочитать, записать, снять лог, откатиться

Дата: **2026-10-07**. Документ — для человека без опыта. Он описывает только то,
что подтверждено публичными инструкциями (ссылки в §9) и нашими инструментами;
шагов «на память» здесь нет. Если что-то расходится с твоим ЭБУ — остановись и
спроси, а не действуй наугад.

> **Область доверия.** Наши файлы проверены **байт-в-байт и по контрольным
> суммам** («bytes+crc verified»), но **на живой машине не проверялись**
> («field verified» — нет). Первый выезд — по протоколу
> `docs/FIELD_TEST_PROTOCOL_RU.md`, самый осторожный вариант.

## 1. Что нужно

* Ноутбук с Windows (WinKFP/BMW Standard Tools, MS4x Flasher, MS45-Flasher —
  только Windows) и **стабильное питание**: внешний зарядник или «прикуривание»
  от второй машины **не менее 10 А** — на всё время записи
  ([WinKFP-инструкция](https://www.e46fanatics.com/threads/diy-how-to-flash-update-dme-or-egs.1324566/)).
* Кабель: INPA-совместимый K-line/OBD2. Для MS45-Flasher задержка (latency)
  порта ставится **1 мс** ([MS45-Flasher](https://github.com/terraphantm/MS45-Flasher)).
* Генератор: этот репозиторий (`python3 tools/torquex.py …`).
* Логи: **Test0** (`docs/TEST0_CLIENT_GUIDE_RU.md`).

## 2. Шаг 0. Заводской сток — до всего остального

Сделай **полное чтение** ЭБУ и сохрани его как бэкап:

| ЭБУ | Чем читать | Что получится |
| --- | --- | --- |
| MS42, MS43 | MS4x Flasher | «Partial Read» — 64 КиБ калибровки (~20 с), «Full Read» — 512 КиБ (~120 с) |
| MS45 | MS45-Flasher | «Read DME»; для полного бэкапа включи «full binary» — получишь пару файлов `_Flash` и `_mpc`, нужны **оба** |
| MS41 | своим инструментом чтения/бутмода | калибровка 24 КиБ или полное чтение 256 КиБ |

Факты, которые важно знать ([MS4x Flasher](https://www.ms4x.net/index.php?title=MS4x_Flasher)):

* полное чтение 512 КиБ **не включает область ISN** — это штатно;
* «Partial Read» содержит только калибровку; для записи калибровки его
  достаточно, для бэкапа ЭБУ — нет;
* если ЭБУ «read locked» для DS2, чтение делают в **boot mode** (JMGarage
  Flasher) — тогда читай инструкцию именно к нему;
* MS4x Flasher сам умеет **пересчитывать контрольные суммы** и сбрасывать
  адаптации; в наших файлах суммы уже пересчитаны, но проверить не лишнее.

**Правило:** файл, записанный в ЭБУ, всегда должен быть получен из **твоего**
стока. Чужой сток не записывают никогда.

## 3. Шаг 1. Определить ЭБУ и выбрать вариант

```bash
python3 tools/torquex.py detect /путь/к/твоему_стоку.bin
python3 tools/torquex.py variants
```

`detect` сам скажет ЭБУ, версию и поддержана ли она. Если версия не поддержана,
генератор не выпустит файл: для MS43 сначала обновляют ЭБУ до **430069** (это
делает MS4x Flasher), потому что адреса и границы сняты только с проверенных
версий.

Варианты:

* **v1 — базовый** (начни с него): зажигание до +1.5° на подтверждённых картах,
  лимитеры и разрешённые функции отдельными запросами; логов не требует;
* **v2 — расширенный**: нужен лог Test0 (зажигание/топливо по логу, ВАНос по
  логу фаз, обороты с подтверждениями);
* **v3 — без катализатора**: v2 + хлопки и слой диагностики; только при
  физически снятом катализаторе, с подтверждением правовой справки.

## 4. Шаг 2. Собрать файл

```bash
python3 tools/torquex.py build \
  --file /путь/к/заводскому_стоку.bin \
  --variant v1 \
  --out  /путь/готовый.bin \
  --note /путь/наряд.md \
  --manifest /путь/манифест.json
```

Что появится:

* `готовый.bin` — только если статус **BUILT** (ядро не пишет ничего вне
  разрешённых ячеек и само пересчитывает суммы);
* `наряд.md` — что именно и почему изменено, границы, чего не сделано и какие
  данные нужны;
* `манифест.json` — sha256 стока и результата, версия генератора, для проверки и
  отката.

Отказы печатаются понятным текстом (коды сохраняются), на русском и английском,
например:

```
[CAL_VERSION_UNSUPPORTED]: Версия ЭБУ не поддерживается генератором — …
SUPPORTED_ECU: This ECU version is not supported — …
```

Объяснить любой код можно отдельно: `python3 tools/torquex.py explain <КОД>` и
`--lang en`.

## 5. Шаг 3. Запись

Порядок, общий для MS41–MS45 (по публичным инструкциям, §9):

1. зарядник/питание ≥ 10 А подключены, все потребители выключены;
2. ключ — положение 2 (зажигание, двигатель не запускать);
3. кабель подключён; **не трогай разъём во время записи**;
4. запись:
   * MS42/MS43 — MS4x Flasher: «Load file» → «Full write» (если менялась только
     калибровка, можно «Partial write» — он не трогает код программы);
   * MS45 — MS45-Flasher: «Load file» → «Flash Tune»; полные файлы — «Load
     file» + «Load file 2 (MPC)» → «Flash Program». **Не смешивай файлы от
     разных ЭБУ**: автор прямо предупреждает, что при несовпадении ЭБУ может
     перестать загружаться;
   * MS41 — своим проверенным инструментом для этой калибровки.
5. дождись сообщения об успехе (у WinKFP по времени: MS43 ~20 минут, MS45.1
   ~43 минуты — это заводская программа, у MS4x Flasher 512 КиБ ~2 минуты);
6. выключи зажигание, подожди минуту, включи снова;
7. сними коды ошибок и **сбрось адаптации** штатной диагностикой (INPA / MS4x
   Flasher / PA Soft — как удобнее);
8. запусти двигатель, дай прогреться, послушай и посмотри поведение.

Чего не делать:

* не прерывать питание и не выдёргивать кабель;
* не нажимать в WinKFP «bootsector update» без прямой необходимости — по
  [Bimmerlabs](https://www.bimmerlabs.com/help) этот чекбокс в ряде случаев
  приводит к «кирпичу»;
* не прошивать файл, у которого не сошёлся `sha256` с манифестом;
* MS41/MS42 в ряде случаев прошиваются в **boot mode** на снятом/разобранном
  ЭБУ (это описано в сообществах, например JMGarage) — если ты не уверен,
  отдай эту работу тому, кто уже делал её на такой машине;
* не верить обещаниям «+X л.с.»: мы мощность не обещаем и не измеряем её.

## 6. Шаг 4. Проверить выпущенный файл

```bash
python3 -m MS45.tools.stages --verify-manifest /путь/манифест.json --image /путь/готовый.bin
# MS43: python3 -m MS43.tools.stages --verify-manifest … --image …
```

Ожидаемый ответ — **VERIFIED**: и байты, и контрольные суммы, и «вне плана
ничего не менялось».

## 7. Шаг 5. Лог Test0 (обязателен для варианта 2/3 и для любого отчёта)

Как снять лог, что включить и как отправить — `docs/TEST0_CLIENT_GUIDE_RU.md`
(каналы, пресеты под новые функции — там же, §5). Коротко: лог снимается **до и
после** записи, на прогретом моторе, с разгонами до отсечки и участком ровной
частичной нагрузки. Анализ лога делают наши инструменты
(`tools/pack_log_analyzer.py`), клиент ничего не считает руками.

## 8. Шаг 6. Откат на сток одной командой

```bash
python3 tools/torquex.py rollback \
  --manifest /путь/манифест.json \
  --stock    /путь/заводской_сток.bin \
  --written  /путь/готовый.bin \
  --out      /путь/сток_для_записи.bin
```

Инструмент сверит `sha256` стока с манифестом, проверит выпущенный файл и
контрольные суммы восстановленного образа. Дальше — записать
`сток_для_записи.bin` тем же способом, что и тюн, и снова сбросить адаптации.
Помни: файл ЭБУ, из которого делали тюн, — **тот самый**, иначе откат невозможен.

## 9. Источники (проверены 2026-10-07)

* MS4x Flasher, официальная вики: чтение/запись MS42/MS43, размеры и время,
  EWS sync (beta), сброс адаптаций, пересчёт сумм, boot mode для read-locked
  ЭБУ — <https://www.ms4x.net/index.php?title=MS4x_Flasher>
* MS45-Flasher (terraphantm): INPA-совместимый кабель, latency 1 мс, полный
  бэкап = `_Flash` + `_mpc`, предупреждение о несовпадении файлов —
  <https://github.com/terraphantm/MS45-Flasher>
* WinKFP: питание ≥ 10 А, положение ключа, время записи MS43 ~20 мин /
  MS45.1 ~43 мин, сброс адаптаций после —
  <https://www.e46fanatics.com/threads/diy-how-to-flash-update-dme-or-egs.1324566/>
  и <https://www.bimmerlabs.com/help> (bootsector update, порядок program → data)
* MS41/MS42: чтение/запись в boot mode, синхронизация EWS после «virgin»
  прошивки — практика сообществ (JMGarage; forum-темы). Мы её не проверяли и не
  рекомендуем новичку делать это самостоятельно.
* Логи Test0 — официальные страницы проекта и наши документы
  (`docs/TEST0_CLIENT_GUIDE_RU.md`, `docs/TEST0_WEB_ANALYSIS_RU.md`).

Про ограничения и что осталось «ждёт данных» — `docs/RELEASE_CHECKLIST_RU.md` и
`docs/HANDOFF_NEXT_SESSION_RU.md`.
