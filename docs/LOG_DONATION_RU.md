# Добровольная передача логов проекту

Статус: код готов, **по умолчанию выключено** (`TORQUEX_LOG_DONATION` не задан).
Включает владелец на проде после проверки юристом (чек-лист ниже).

## 1. Что видит пользователь

Страница `web/logs.html` («Разобрать лог и помочь проекту», ссылка в подвале):

1. файл CSV или `.db` Test0 (до 1 МиБ — прежний предел `/logs`);
2. пакет: зажигание / топливо / VANOS;
3. флажок «Разобрать мой лог» — обязателен (`consent=true`, как раньше);
4. флажок «Передать очищенную копию лога проекту…» — **отдельный, выключен по
   умолчанию**, скрыт, если `GET /health` отвечает `log_donation: false`.

После передачи пользователь один раз видит **код удаления** вида
`<log_id>.<delete_token>` и поле «Удалить мой лог». Код не сохраняется ни в
браузере, ни в адресе; на сервере — только `sha256(delete_token)`.

Страница `web/privacy.html` описывает то же простым языком.

## 2. API

* `POST /logs` — новое поле формы `share_consent` (по умолчанию `false`).
  Без него поведение прежнее: на диск не пишется ничего.
  С ним, после **успешного** анализа (ворота пройдены), ответ получает поле
  `share`:
  * `{"status": "STORED", "log_id", "delete_token", "expires", "consent_version", ...}`;
  * или `{"status": "NOT_STORED", "code", "title_ru", "title_en"}` — анализ при
    этом остаётся в ответе (`evidence_id` как раньше).
* `DELETE /logs/{log_id}` с заголовком `X-Delete-Token` → `200 {"status":"DELETED"}`
  или `404 LOG_DELETE_NOT_FOUND` (одинаковый ответ для «нет такой» и
  «неверный код»). Работает и при выключенной передаче.
* `GET /health` → `log_donation: true|false`, `log_retention_days`.

Коды отказа (тексты RU/EN — `tools/refusals.py`): `LOG_SHARE_DISABLED`,
`LOG_SCRUB_FAILED`, `LOG_STORE_FULL`, `LOG_RATE_LIMITED`, `LOG_SHARE_TOO_LARGE`
(добавлен сверх задания: копия больше предела), `LOG_DELETE_NOT_FOUND`.

## 3. Очистка (`server/log_store.py`)

* **Allowlist.** В копию попадают только `time` и каналы, известные анализатору
  (`docs/pack_log_requirements.json`, кроме служебного `knock_cylinders`),
  каталогу Test0 (`docs/test0_channels.json`) и `knock_cyl_1..6`. Всё прочее
  (колонки VIN/FGNR/ISN, комментарии, IP, пути, строки job-ов, `prgName`,
  чужие таблицы `.db`) не попадает в копию, потому что его нет в списке.
* **Пересборка.** Лог читается тем же разборщиком, что и для анализа
  (`pack_log_analyzer.read_log_table`; `.db` — SQLite `mode=ro`, только
  `jobs`/`result_definitions`/`job_executions`), затем записывается новый CSV:
  UTF-8 (фактически ASCII), LF, `,`, точка, имена каналов — канонические
  (`rpm`, `load`, `lambda_wideband`…). Исходные байты не хранятся.
* **Числа.** Не более 4 знаков после точки, |x| < 1e9; NaN/inf/текст → пустая
  ячейка. AFR уже переведён анализатором в λ.
* **Время от нуля.** Ось времени сдвигается к первой точке: абсолютная дата и
  время поездки не сохраняются.
* **Самопроверка** (`verify_scrubbed`) после очистки, независимо от кода
  очистки: заголовок только из allowlist и начинается с `time`; каждая ячейка
  `^-?[0-9]{1,9}(\.[0-9]{1,4})?$`; нет 17-символьных VIN-подобных подстрок
  (`[A-HJ-NPR-Z0-9]{17}`, без учёта регистра); нет `@`, CR, NUL, не-ASCII.
  Любое нарушение → `LOG_SCRUB_FAILED`, ничего не пишется.

Каналы `.csv` переименованы в канонические, поэтому сохранённую копию
`tools/pack_log_analyzer.py` «как есть» не распознаёт (у части каналов
каноническое имя не является алиасом). Для работы с копиями нужен маленький
загрузчик (не сделан).

## 4. Хранение

* Каталог `TORQUEX_LOG_STORE` (по умолчанию `<repo>/data/logs`, в `.gitignore`).
  Внутри `web/` — отказ при старте.
* Файлы: `<id>.csv` и `<id>.meta.json`, `id = secrets.token_urlsafe(18)`.
  Пользовательские строки в путь не попадают; `log_id` из запроса проверяется
  регулярным выражением и что путь остаётся в каталоге. Запись атомарная
  (временный файл + `os.replace`), права `0600` (на Linux).
* Метаданные: `id`, `created`/`expires` (дата без времени), `platform` (если
  определяется по логу — сейчас только `.db`, иначе `null`), `version` (всегда
  `null`: по логу версия блока не определяется), `package`, `channels`,
  `size_bytes`, `rows`, `sha256`, `consent_version` (`CONSENT_VERSION`),
  `delete_token_sha256`. **Нет** IP, хеша IP, VIN, имени файла, токена.
* Журнал (`TORQUEX_JOURNAL_PATH`): строки `LOG_SHARED` (только `ip_hash` — для
  лимита) и `LOG_DELETED`; без `log_id` и без sha копии.

## 5. Сроки и лимиты

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `TORQUEX_LOG_DONATION` | выкл. | `on`/`true`/`1`/`yes` — включить приём копий |
| `TORQUEX_LOG_STORE` | `data/logs` | каталог копий |
| `TORQUEX_LOG_RETENTION_DAYS` | `365` | срок хранения |
| `TORQUEX_LOG_STORE_MAX_BYTES` | `2147483648` (2 ГиБ) | потолок каталога → `LOG_STORE_FULL` |
| `TORQUEX_LOG_MAX_STORED_BYTES` | `20971520` (20 МиБ) | предел одной копии → `LOG_SHARE_TOO_LARGE` |
| `TORQUEX_LOG_SHARES_PER_IP_PER_DAY` | `5` | передач на хеш IP в сутки → `LOG_RATE_LIMITED` |

* Автоудаление: `purge_expired()` при каждом старте сервиса (и при выключенной
  передаче) и `tools/purge_logs.py` (`--dry-run` — только посчитать) для cron.
  Срок копии — меньшее из `expires` и `created + текущий срок`: уменьшение
  срока применяется к старым копиям. Копии без читаемых метаданных удаляются,
  чужие файлы не трогаются.
* Лимит на IP считается по журналу **в памяти процесса**: после рестарта
  счётчик обнуляется (как и прочие лимиты сервиса).

## 6. Известные ограничения

* `.db` Test0 сейчас ни для одного пакета не проходит ворота анализа (в PRG нет
  `knock_retard`, а широкополосная лямбда — только внешний CSV-канал), поэтому
  копия `.db` на практике не сохранится. Очистка `.db` реализована и покрыта
  тестами на уровне функции.
* Логи, не прошедшие ворота анализа, не сохраняются (по заданию: «после
  успешного анализа»).
* Время в метаданных — дата (UTC), не время: снижает связываемость с журналом.
* На странице срок «365 дней» написан текстом; при смене
  `TORQUEX_LOG_RETENTION_DAYS` обновить `privacy.*`/`logs.*` в `web/i18n.js`.
* Канала связи кроме страницы «Поддержать» (Boosty/PayPal) нет — для запросов
  субъектов данных его, вероятно, придётся добавить (решает владелец/юрист).
